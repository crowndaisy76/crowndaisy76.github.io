Project Objective

컨테이너 환경에서 유실되는 보안 이벤트 문제를 해결하기 위해, 커널 레벨 수집과 고속 상관분석 구조를 결합한 파이프라인을 설계했습니다.

01. Problem & Goal

AS-IS
  • 컨테이너 종료 시 침해 흔적이 완전히 소멸하는 구조적 한계를 확인했습니다.
  • User-space 기반 수집 구조에서 트래픽 피크 시 커널 이벤트가 Drop되는 문제를 식별했습니다.
  • 이기종 로그가 분리되어 있어 공격자의 수평 이동을 재구성할 수 없는 상태였습니다.
TO-BE
  • eBPF 기반 실시간 수집망: 커널 수집 구조를 도입하여 이벤트 유실을 제거했습니다.
  • 다차원 상관 분석 구조: 공통 식별자(8-Tuple) 기반 정규화를 설계하여 로그를 하나의 공격 시나리오로 재구성했습니다.

01. My Role & Decision

Decision: Tetragon 채택
WHY
기존 User-space 기반 수집 구조에서 이벤트 Drop이 발생하는 원인을 분석한 결과, Context Switching 오버헤드가 병목이라는 결론을 도출했습니다.
IMPACT
커널 레벨에서 직접 이벤트를 필터링하는 구조로 전환하여, 고부하 환경에서도 Drop 없는 안정적인 수집 체계를 확보했습니다.
Decision: ClickHouse 아키텍처 전환 주도
WHY
기존 OpenSearch 환경에서 조인 기반 상관분석이 병목이 되어 실시간 분석이 불가능한 구조임을 확인했습니다.
IMPACT
ClickHouse 기반 구조를 설계하고 PoC로 검증하여 전체 아키텍처를 고속 분석 중심 구조로 전환했습니다.

Key Technologies

Rust STIX 2.1 Python RAG (Vector DB)

Project Objective

분산된 포렌식 도구 환경에서 발생하는 분석 단절 문제를 해결하기 위해, 아티팩트 파싱부터 CTI 연계까지 통합된 분석 파이프라인을 설계했습니다.

02. Problem & Goal

AS-IS
  • 도구 간 데이터 연계가 없어 분석 결과가 단절되는 문제를 확인했습니다.
  • 분석가가 수동으로 이벤트를 조합해야 하며 초기 대응 속도가 크게 저하되는 구조였습니다.
TO-BE
  • 단일 파이프라인 통합: 한 번의 실행으로 디스크, 메모리, 아티팩트 데이터를 모두 추출하고 분석하는 파이프라인을 구축했습니다.
  • 파편화된 분석 과정을 하나로 묶어 즉각적인 위협 시나리오를 도출하고 RAG 기반 인텔리전스와 연동했습니다.

02. My Role & Decision (1/2)

Decision: Rust 기반 파서 아키텍처 설계
WHY
대용량 디스크 이미지를 처리하는 과정에서 Python 기반 파서의 메모리 사용량 증가와 GC로 인한 지연 문제를 확인했습니다.
CHALLENGE
Rust로 전환 시, 복잡한 바이너리 구조 파싱 과정에서 lifetime과 ownership 관리로 인해 구현 난이도가 급격히 증가했습니다.
RESOLUTION
Zero-copy 기반 파싱 구조를 설계하고, 필요한 구간만 선택적으로 메모리에 로드하는 방식으로 메모리 사용을 최소화했습니다.
IMPACT
대용량 아티팩트 처리 시 메모리 안정성과 처리 속도를 동시에 확보했습니다.
Decision: 이벤트 상관분석 모델 설계
WHY
개별 아티팩트 분석 결과만으로는 공격 흐름을 설명할 수 없는 구조적 한계를 확인했습니다.
CHALLENGE
서로 다른 출처의 이벤트(파일, 프로세스, 네트워크)를 일관된 기준으로 연결할 수 있는 공통 모델이 필요했습니다.
RESOLUTION
Process ID, File Path, Network Endpoint를 기준으로 이벤트를 정규화하고, 시간 기반 그래프 구조로 연결하는 모델을 설계했습니다.
IMPACT
단편적인 이벤트를 하나의 공격 시나리오로 재구성할 수 있는 기반을 마련했습니다.

02. My Role & Decision (2/2)

Decision: STIX 2.1 기반 데이터 모델링
WHY
분석 결과가 내부 구조에 종속될 경우 외부 CTI와의 연계가 불가능한 문제가 있었습니다.
CHALLENGE
로컬 아티팩트 데이터를 STIX Object 구조에 맞게 매핑하는 과정에서 스키마 불일치 문제가 발생했습니다.
RESOLUTION
아티팩트 데이터를 Indicator, Observed Data 등 STIX 객체로 분리 매핑하고, 관계(Relationship)를 명시적으로 정의하는 구조를 설계했습니다.
IMPACT
분석 결과를 외부 CTI 시스템과 연계 가능한 형태로 확장할 수 있게 되었습니다.
Decision: CTI 기반 RAG 분석 구조 설계
WHY
IoC 기반 탐지만으로는 공격의 맥락을 설명하기 어려운 한계를 확인했습니다.
CHALLENGE
탐지 이벤트와 외부 CTI 데이터를 연결할 때, 단순 키워드 매칭으로는 의미 있는 결과를 도출하기 어려웠습니다.
RESOLUTION
이벤트를 벡터화하여 유사한 공격 사례를 검색하고, 해당 컨텍스트를 기반으로 분석 결과를 생성하는 RAG 파이프라인을 설계했습니다.
IMPACT
탐지 이벤트를 단순 경고가 아닌, 대응 가능한 인텔리전스로 확장했습니다.
