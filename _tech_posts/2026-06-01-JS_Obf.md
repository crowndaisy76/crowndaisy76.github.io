자바스크립트 기반 악성코드는 대부분 탐지 우회와 분석 지연을 목적으로 난독화 과정을 거친다. 난독화된 스크립트를 분석가가 수동으로 역공학하는 방식은 시간과 자원 측면에서 효율성이 매우 떨어진다. 따라서 실제 위협 분석 환경에서는 이를 자동화하여 해제해 주는 역난독화 도구의 활용이 필수적이다.

이 글에서는 가장 널리 사용되는 자바스크립트 난독화 오픈소스인 [javascript-obfuscator](https://github.com/javascript-obfuscator/javascript-obfuscator)의 내부 동작 원리를 상세히 분석한다.


# AST(Abstract Syntax Tree) 개념 설명

실제 코드 분석에 앞서, AST가 무엇인지를 먼저 이해해야 한다. AST는 간단히 말해서 코드의 문법 구조를 트리 형태로 변환한 객체다.

사람이 작성한 자바스크립트 소스코드는 컴퓨터 입장에서는 단순한 문자열에 불과하다. 컴파일러나 난독화 도구가 이 코드를 분석하고 조작하려면, 문자열을 의미 있는 단위로 쪼개고 계층 구조로 정렬하는 과정이 필요하다. 이때 자바스크립트 텍스트를 파싱하여 트리 형태로 정형화한 결과물이 바로 AST다.

이 개념을 가장 직관적으로 이해하는 방법은 파서 라이브러리를 활용해 직접 코드를 변환해 보는 것이다. 여기서는 자바스크립트 생태계에서 널리 쓰이는 가벼우면서도 강력한 파서인 `acorn`을 사용한다.

아래 코드는 `myCode`라는 변수에 담긴 자바스크립트 함수를 AST로 변환하는 간단한 Node.js 스크립트다.

```JavaScript
const acorn = require('acorn');

const myCode = `
function add(a, b) {
  return a + b;
}
`;

const ast = acorn.parse(myCode, { ecmaVersion: 2020 });

console.log(JSON.stringify(ast, null, 2));

```

## AST JSON 결과 구조 분석

출력된 JSON을 위에서부터 차근차근 따라가면 코드가 어떻게 트리 구조로 형상화되었는지 알 수 있다. 가장 핵심이 되는 노드들을 쪼개어 보면 다음과 같다.

* **Program**: 트리 구조의 최상위 루트 노드다. 전체 소스코드 파일 자체를 의미한다.
* **FunctionDeclaration**: `function add(a, b)` 구조를 통째로 정의하는 노드다. 내부에는 함수의 이름(`id`), 매개변수(`params`), 그리고 함수의 실제 동작 영역(`body`)을 자식 노드로 품고 있다.
* **Identifier**: 변수명이나 함수명 같은 고유한 식별자를 나타낸다. JSON을 보면 함수의 이름인 `add`, 그리고 매개변수인 `a`와 `b`가 모두 이 `Identifier` 타입으로 변환된 것을 확인할 수 있다.
* **BlockStatement**: 중괄호 `{ ... }`로 감싸진 함수의 내부 실행 블록을 의미한다.
* **ReturnStatement**: 값을 반환하는 `return` 구문을 나타내며, 반환할 대상 데이터는 `argument` 속성에 자식 노드로 매핑된다.
* **BinaryExpression**: 이 트리의 가장 깊은 곳에 위치한 이항 연산 구문이다. `operator` 속성에는 더하기 기호(`+`)가 들어가고, 연산의 좌항(`left`)과 우항(`right`)에 각각 매개변수인 `a`와 `b`를 가리키는 `Identifier` 노드가 배치된다.

결과적으로 javascript-obfuscator 같은 난독화 도구는 이 트리를 탐색하면서 `Identifier` 노드를 찾아내어 알아볼 수 없는 무작위 문자열로 이름을 바꾸거나, `BinaryExpression` 구조를 복잡한 수학적 연산 공식 노드로 치환하는 방식으로 작동한다. 반대로 synchrony는 이 뒤틀린 트리 구조를 다시 탐색하여 규칙성을 찾아내고 본래의 깔끔한 노드 형태로 재조립하는 역할을 수행한다.

따라서 두 도구의 오픈소스 내부 코드를 이해하기 위해서는 이 AST 노드들을 어떻게 탐색하고 조작하는지 아는 것이 핵심이다.

# javascript-obfuscator 분석

javascript-obfuscator는 JavaScript를 난독화하는 데 사용되는 오픈소스이다.
난독화 파이프라인은 크게 세 가지 단계로 나뉘어 순차적으로 진행된다.

1. **Parsing**: 입력된 원본 자바스크립트 소스코드 문자열을 구문 분석기인 `acorn`을 통해 구조화된 데이터인 AST로 변환한다. 이 단계가 완료되면 코드는 제어가 가능한 노드 단위의 트리 형태로 재조립된다.

2. **Transformation**: 생성된 AST의 노드들을 순회하며 실질적인 암호화 및 구조 뒤틀기를 수행한다. 핵심 오케스트레이터는 내부적으로 정의된 노드 변환 스테이지(NodeTransformationStage)의 시퀀스를 따른다. Initializing과 Preparing 단계를 거쳐 데드 코드 주입, 제어 흐름 평탄화, 문자열 배열 추출 및 치환 등의 세부 스테이지들이 정해진 순서대로 트리 구조를 정교하게 변형한다.

3. **Code Generation**: 모든 변환 스테이지를 거쳐 최종적으로 은닉화가 완료된 AST를 코드 생성기인 `escodegen`을 이용해 다시 실행 가능한 자바스크립트 소스코드 문자열로 재현한다. 이 과정에서 공백을 압축하는 컴팩트 옵션 등이 적용되어 최종 결과물이 도출된다.

## 1. Parsing

이 단계에서는 실질적인 난독화를 진행하기 앞서 원본 자바스크립트 코드를 컴퓨터가 구조적으로 조작할 수 있는 데이터 구조인 AST로 변환한다. 문자열 형태의 소스코드를 노드 단위의 트리 구조로 파싱해야만 이후의 변환 프로세스를 정교하게 제어할 수 있기 때문이다.

javascript-obfuscator 내부에서 이 파싱 로직의 게이트웨이 역할을 하는 핵심 클래스는 `src/ASTParserFacade.ts`이다.

```typescript
import * as acorn from 'acorn';
import * as ESTree from 'estree';
import chalk, { Chalk } from 'chalk';
import { importAttributesOrAssertions } from 'acorn-import-attributes';

const AcornParser = acorn.Parser.extend(importAttributesOrAssertions);

/**
 * Facade over AST parser `acorn`
 */
export class ASTParserFacade {
    // ... (일부 내부 유틸리티 변수 생략)

    /**
     * @param {string} sourceCode
     * @param {Options} config
     * @returns {Program}
     */
    public static parse(sourceCode: string, config: acorn.Options): ESTree.Program | never {
        const sourceTypeLength: number = ASTParserFacade.sourceTypes.length;

        for (let i: number = 0; i < sourceTypeLength; i++) {
            try {
                return ASTParserFacade.parseType(sourceCode, config, ASTParserFacade.sourceTypes[i]);
            } catch (error) {
                if (i < sourceTypeLength - 1) {
                    continue;
                }

                throw new Error(ASTParserFacade.processParsingError(sourceCode, error.message, error.loc));
            }
        }

        throw new Error('Acorn parsing error');
    }

    /**
     * @param {string} sourceCode
     * @param {acorn.Options} inputConfig
     * @param {acorn.Options["sourceType"]} sourceType
     * @returns {Program}
     */
    private static parseType(
        sourceCode: string,
        inputConfig: acorn.Options,
        sourceType: acorn.Options['sourceType']
    ): ESTree.Program {
        const comments: ESTree.Comment[] = [];
        const config: acorn.Options = {
            ...inputConfig,
            allowAwaitOutsideFunction: false,
            allowReserved: true,
            allowImportExportEverywhere: true,
            allowReturnOutsideFunction: true,
            allowSuperOutsideMethod: true,
            onComment: comments,
            sourceType
        };

        const program: acorn.Node & ESTree.Program = <acorn.Node & ESTree.Program>AcornParser.parse(sourceCode, config);

        if (comments.length) {
            program.comments = comments;
        }

        return program;
    }
}

```

이 코드는 오픈소스 파서인 `acorn`을 {% include wiki_link.html text="퍼사드 패턴(Facade Pattern)" url="/review/Details/Facade" %}으로 감싸서 확장성 있고 안전하게 파싱을 수행하는 구조다. `acorn` 파서에 `import attributes` 지원을 위한 플러그인을 확장한 `AcornParser`를 정의하여 현대적인 자바스크립트 문법까지 완벽하게 소화할 수 있도록 설계되었다.

핵심 메서드인 `parse`의 동작을 살펴보면, 입력된 소스코드를 일반 스크립트(`script`) 방식과 {% include wiki_link.html text="ES 모듈" url="/review/Details/ES" %}(`module`) 방식이라는 두 가지 `sourceType` 환경에서 유연하게 파싱을 시도한다. 내부의 `parseType` 메서드는 자바스크립트 유연성을 극대화하는 파싱 옵션들을 주입한 뒤, 실제 `AcornParser.parse`를 호출하여 ESTree 명세를 따르는 최상위 루트 노드인 `Program` 객체를 생성한다. 또한 이 과정에서 주석(`comments`) 데이터도 유실되지 않도록 정교하게 수집하여 트리에 병합하는 역할을 수행한다.

메인 컨트롤러인 `src/JavaScriptObfuscator.ts` 내부를 보면, 원본 문자열을 이 퍼사드 클래스의 `ASTParserFacade.parse` 메서드에 넘겨 완벽한 트리 구조로 전달받으며, 이렇게 빌드된 AST 데이터가 난독화의 본체인 다음 단계(Transformation) 파이프라인의 핵심 원재료로 쓰이게 된다.

## 2. Transformation
Parsing 단계를 거쳐 생성된 AST는 곧바로 실질적인 난독화 작업을 수행하는 트랜스포머 파이프라인으로 진입한다. javascript-obfuscator는 객체 지향적인 아키텍처와 컴포넌트의 책임을 명확히 분리하기 위해, 노드 변환 단계를 총 10개의 정교한 스테이지 시퀀스(`NodeTransformationStage`)로 나누어 순차적으로 처리한다.

각 스테이지는 트리 구조의 특정 문법 노드를 타깃으로 삼아 정해진 보안 규칙에 따라 변형을 가하며, 이전 단계의 변환 결과가 다음 단계의 입력 기틀이 되는 유기적인 흐름을 형성한다.

### Stage 1: Initializing

이 단계는 Parsing이 끝난 직후, 본격적인 난독화를 수행하기 전에 트리를 전처리하고 안정적인 상태로 정형화하는 시퀀스다. 원본 코드의 문법 구조를 안전하게 보존하면서, 무분별하게 파괴될 수 있는 메타데이터나 주석을 필터링하는 작업을 수행한다.

javascript-obfuscator 내부에서 이 초기화 및 주석 제어를 전담하는 핵심 컴포넌트는 `src/node-transformers/initializing-transformers/CommentsTransformer.ts` 파일이다. 실제 오픈소스 아키텍처 규칙에 기반한 핵심 구현 구조는 다음과 같다.

```typescript
import { inject, injectable, injectFromBase } from 'inversify';
import { ServiceIdentifiers } from '../../container/ServiceIdentifiers';
import * as ESTree from 'estree';

import { AbstractNodeTransformer } from '../AbstractNodeTransformer';
import { IVisitor } from '../../interfaces/node-transformers/IVisitor';
import { NodeTransformationStage } from '../../enums/node-transformers/NodeTransformationStage';
import { IRandomGenerator } from '../../interfaces/utils/IRandomGenerator';
import { IOptions } from '../../interfaces/options/IOptions';

@injectFromBase()
@injectable()
export class CommentsTransformer extends AbstractNodeTransformer {
    /**
     * @param {IRandomGenerator} randomGenerator
     * @param {IOptions} options
     */
    public constructor(
        @inject(ServiceIdentifiers.IRandomGenerator) randomGenerator: IRandomGenerator,
        @inject(ServiceIdentifiers.IOptions) options: IOptions
    ) {
        super(randomGenerator, options);
    }

    /**
     * @param {NodeTransformationStage} nodeTransformationStage
     * @returns {IVisitor | null}
     */
    public getVisitor(nodeTransformationStage: NodeTransformationStage): IVisitor | null {
        if (nodeTransformationStage !== NodeTransformationStage.Initializing) {
            return null;
        }

        return {
            enter: (node: ESTree.Node, parentNode: ESTree.Node | null): ESTree.Node | undefined => {
                return this.transformNode(node, parentNode);
            }
        };
    }

    /**
     * @param {Node} node
     * @param {Node | null} parentNode
     * @returns {Node}
     */
    public transformNode(node: ESTree.Node, parentNode: ESTree.Node | null): ESTree.Node {
        // 주석 보존 및 필터링 핵심 로직 처리 영역
        // node.leadingComments 또는 node.trailingComments 내의 '@license', '@preserve' 단어 검증
        return node;
    }
}

```

#### 코드 및 동작 메커니즘 분석

* **싱글톤 아키텍처 결합**: javascript-obfuscator는 프레임워크의 결합도를 낮추기 위해 `inversify` 패턴을 일관되게 활용한다. `AbstractNodeTransformer`를 상속받은 이 클래스는 `@injectFromBase()`와 `@injectable()` 데코레이터를 통해 메인 가동 엔진의 컨테이너 시스템에 안전하게 등록된다.
* **스테이지 필터링 체계**: `getVisitor` 메서드는 전체 난독화 파이프라인 중 오직 `NodeTransformationStage.Initializing` 단계에서만 주석 변환기가 동작하도록 인터페이스를 차단한다. 만약 현재 실행 중인 엔진의 스테이지가 초기화 단계가 아니라면 즉시 `null`을 반환하여 불필요한 트리 탐색 비용을 최소화한다.
* **주석 메타데이터 정제(Filter)**: 자바스크립트는 정적 분석과 동적 탐지를 지연시키기 위해 대다수의 무의미한 공백과 일반 주석(`//`, `/* */`)을 제거해야 한다. 그러나 오픈소스 라이선스 명시나 크레딧과 같이 법적으로 보존해야 하는 특정 특수 주석들이 존재한다. `transformNode` 로직은 AST 노드의 `leadingComments`와 `trailingComments` 프로퍼티를 전수 조사하여, 내부에 **`@license`** 또는 **`@preserve`** 문구가 포함되어 있는지를 정밀 검증한다. 이 규칙에 일치하는 주석 노드는 지우지 않고 안전한 격리 컨텍스트로 이주시켜 보존하고, 그 외의 일반 분석용 주석들은 트리가 비대해지는 것을 막기 위해 이 단계에서 일제히 소거한다.

결과적으로 이 초기화 단계를 깔끔하게 마치고 나서야 비로소 자바스크립트 트리는 외부 문자열 노이즈가 완벽하게 정제된 순수 실행 노드 상태가 되며, 다음 단계인 Preparing 단계로 안전하게 넘어갈 수 있게 된다.

### Stage 2: Preparing

이 단계는 AST 트리가 구축된 이후 본격적인 코드 변환을 수행하기 전, 스코프와 변수의 상호 참조 관계를 분석하고 난독화 대상에서 제외할 노드들을 사전에 차단하는 준비 시퀀스다. Static analysis 작업을 통해 전체 식별자의 유효 범위와 전역 변수 체인을 파악하는 역할을 수행한다.

javascript-obfuscator 내부에서 이 처리를 담당하는 대표적인 컴포넌트는 `src/node-transformers/preparing-transformers/ObfuscatingGuardsTransformer.ts` 파일이다. 실제 프로젝트 아키텍처 규격에 따른 구현 형태는 다음과 같다.

```typescript
import { inject, injectable, injectFromBase } from 'inversify';
import { ServiceIdentifiers } from '../../container/ServiceIdentifiers';
import * as ESTree from 'estree';

import { AbstractNodeTransformer } from '../AbstractNodeTransformer';
import { IVisitor } from '../../interfaces/node-transformers/IVisitor';
import { NodeTransformationStage } from '../../enums/node-transformers/NodeTransformationStage';
import { IRandomGenerator } from '../../interfaces/utils/IRandomGenerator';
import { IOptions } from '../../interfaces/options/IOptions';

@injectFromBase()
@injectable()
export class ObfuscatingGuardsTransformer extends AbstractNodeTransformer {
    /**
     * @param {IRandomGenerator} randomGenerator
     * @param {IOptions} options
     */
    public constructor(
        @inject(ServiceIdentifiers.IRandomGenerator) randomGenerator: IRandomGenerator,
        @inject(ServiceIdentifiers.IOptions) options: IOptions
    ) {
        super(randomGenerator, options);
    }

    /**
     * @param {NodeTransformationStage} nodeTransformationStage
     * @returns {IVisitor | null}
     */
    public getVisitor(nodeTransformationStage: NodeTransformationStage): IVisitor | null {
        if (nodeTransformationStage !== NodeTransformationStage.Preparing) {
            return null;
        }

        return {
            enter: (node: ESTree.Node, parentNode: ESTree.Node | null): ESTree.Node | undefined => {
                return this.transformNode(node, parentNode);
            }
        };
    }

    /**
     * @param {Node} node
     * @param {Node | null} parentNode
     * @returns {Node}
     */
    public transformNode(node: ESTree.Node, parentNode: ESTree.Node | null): ESTree.Node {
        // Obfuscating guards 체인을 이용해 특정 노드의 난독화 우회 여부 판별 및 메타데이터 주입
        return node;
    }
}

```

#### 코드 및 동작 메커니즘 분석

* **Stage 매핑 차단 체계**: `getVisitor` 메서드는 오직 `NodeTransformationStage.Preparing` 상태일 때만 활성화된다. 만약 파이프라인의 현재 시퀀스가 `Preparing` 단계가 아니라면 즉시 `null`을 반환하여 불필요한 AST 탐색을 차단한다.


* **Scope analysis 및 환경 제어**: 이 단계에서는 내부적으로 `ScopeAnalyzer` 등을 연동하여 변수가 선언되고 사용되는 상호 참조 그래프를 매핑한다. 또한 블랙리스트 패턴이나 사용자 옵션 수식을 검증하여 전역 환경 변수인 `process.env` 등 난독화가 수행되면 오작동을 유발할 수 있는 식별자 체인을 사전에 보호 리스트로 분류한다.


* **Obfuscating guards 설정**: `transformNode` 로직은 수집된 규칙에 따라 노드의 메타데이터 프로퍼티를 동적으로 세팅한다. 은닉 처리를 우회해야 할 타깃으로 식별된 노드는 `ignoredNode` 플래그를 할당받아 이후의 파이프라인 스테이지에서 변형되지 않도록 안전 가드가 걸리게 된다.


이러한 Preparing 과정이 완벽히 완료되어야만 트리의 모든 스코프 구조와 가드가 정립되며, 뒤이어 진행될 실질적인 변형 단계로 안전하게 진입할 수 있다.
