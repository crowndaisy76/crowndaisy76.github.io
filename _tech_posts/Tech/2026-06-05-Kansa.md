Kansa는 PowerShell Remoting을 기반으로 구동되는 Windows 환경 전용 모듈형 침해사고 대응 프레임워크이다. 대상 시스템에 별도의 전용 에이전트를 설치하지 않는 Agentless 방식으로 동작하므로, 조사 대상 엔드포인트에 영구적인 아티팩트를 남기지 않고 시스템 고유 상태의 오염을 최소화하여 데이터 수집의 무결성을 유지하는 데 유리하다.

# Kansa 분석

## PowerShell Remoting

Kansa 프레임워크의 가장 핵심적인 가치는 대상 시스템에 별도의 지속성 에이전트를 설치하지 않고 Windows 빌트인 관리 인프라와 프로토콜만을 사용하여 수백 대 이상의 원격 호스트에서 침해사고 데이터를 수집·통제할 수 있다는 점이다. 이러한 Agentless 원격 제어 및 수집 메커니즘을 지원하기 위해 Kansa 프레임워크 내부의 `DistributedKansa.ps1` 모듈에서는 다음과 같이 원격 세션을 맺고 모듈 명령을 호출하는 실질적인 비즈니스 로직을 사용한다.

```powershell
# DistributedKansa.ps1

# 1. 대상 원격 호스트들과 관리용 WinRM PSSession 생성
$KansaHostSessions = New-PSSession -ComputerName $remoteHosts `
                                   -Credential $Credential `
                                   -SessionOption (New-PSSessionOption -NoMachineProfile -OpenTimeout 2000 -OperationTimeout 5000)

# 2. 비동기 작업(Job) 형태의 원격 스크립트 실행 및 데이터 수집 통제
foreach ($i in 0..$($ServerCount-1)){
    Invoke-Command -Session $KansaHostSessions[$i] `
                   -AsJob `
                   -JobName "RemoteKansaJob_$($KansaHostSessions[$i].ComputerName)" `
                   -ScriptBlock {
                       cd $args[0]; 
                       .\kansa.ps1 $args[1] $args[2] $args[3] $args[4] $args[5] > "$($args[0])\currentRunlog.txt"
                   } `
                   -ArgumentList $KansaRemotePath, $ModulePath, $RemoteTargetListPath, $Target, $Credential
}
```

Kansa가 중앙 작업 스테이션에서 원격 엔드포인트 시스템으로 스크립트를 전달하고 결과를 반환받는 흐름은 Windows 고유의 관리 통신 규격인 {% include wiki_link.html text="WinRM(Windows Remote Management)" url="/tech/Details/WinRM" %} 환경을 전적으로 활용하는 구조다. 마스터 스크립트는 `New-PSSession` 커맨드릿을 호출하여 수집 대상 호스트들의 자격 증명(`-Credential`)을 검증하고, 암호화된 영구적인 PowerShell 세션 파이프를 구축한다. 세션이 성립되면 수집 스크립트 파일들과 구성 정의 파일(`Modules.conf`)을 .NET의 바이트 스트림 형태로 변환하여 WinRM 채널을 통해 원격지의 임시 디렉토리 공간으로 복사 및 스트리밍하므로, 엔드포인트 컴퓨터에 영구적인 바이너리를 상주시키는 가상 에이전트 프로세스가 필요하지 않다.

파일 전송이 완료되면 `Invoke-Command` 아키텍처를 호출하여 앞서 매핑해 둔 각각의 세션 내부에 데이터 수집 명령 스크립트 블록(`-ScriptBlock`)을 실행 파이프라인으로 주입한다. 이때 다수의 엔드포인트를 동시에 스캔하고 네트워크 병목 현상을 방지하기 위해 각 원격 호스트에 할당된 수집 태스크를 비동기 백그라운드 작업(`-AsJob`)으로 분기시킨다. 이를 통해 중앙의 침해사고 대응팀은 대규모 자산에서 오는 응답을 대기하느라 대기 상태에 빠지지 않고 병렬 프로세스로 동시 통제가 가능해진다.

원격 호스트에서 최종 구동된 개별 수집 모듈들은 결과물을 단순한 텍스트로 출력하는 것이 아니라 OS API 계층의 정형화된 PowerShell 네이티브 객체(Object) 상태로 반환한다. 수집된 데이터는 세션을 통해 호출한 마스터 서버로 직렬화되어 전송되므로, 분석가는 중앙 작업 스테이션에서 추가적인 문자열 파싱이나 정규식 가공을 거치지 않고 곧바로 대규모 데이터의 빈도 분석(Stacking)이나 이상 징후 식별 작업을 고속으로 수행할 수 있다.


## Modules

Kansa 프레임워크는 수집하고자 하는 대상 아티팩트와 분석 목적에 따라 독립된 PowerShell 스크립트 형태의 수집 모듈들을 호출하여 실행한다. 프레임워크 내부의 각 모듈은 침해사고 분석 과정에서 핵심 지표가 되는 휘발성 데이터 및 비휘발성 보존 데이터를 수집하기 위해 Windows API, WMI(Windows Management Instrumentation), 레지스트리 하이브 파일 등을 직접 탐색하는 방식을 취한다. 대규모 엔드포인트 환경에서 악성코드의 흔적이나 공격자의 활동 기법을 탐지하기 위해 주로 활용되는 핵심 모듈들의 세부 사양과 소스코드 동작 메커니즘은 다음과 같다.

### 1. PROCESS

공격자가 실행한 악성 프로세스 및 메모리 인젝션 행위를 추적하기 위해 `Get-Tasklist.ps1` 및 `Get-Procdump.ps1` 모듈이 구동된다. `Get-Tasklist.ps1` 모듈은 내부적으로 Windows 관리 인터페이스를 호출하여 현재 가시적으로 구동 중인 모든 프로세스의 관계를 파싱한다.

```powershell
# Get-Tasklist.ps1
Get-WmiObject -Class Win32_Process | Select-Object Name, ProcessId, ParentProcessId, Path, CommandLine, ExecutionState
```

해당 쿼리를 통해 수집된 실행 경로(Path)와 명령줄 인자(CommandLine) 데이터를 기반으로, 정상 경로가 아닌 곳(예: `C:\Users\Public\`)에서 실행된 바이너리나 `svchost.exe`가 비정상적인 부모 프로세스 ID(PPID)를 가지는 등의 변칙적 트리 구조를 선별한다.

더욱 심층적인 악성 여부 판단을 위해 연계되는 `Get-Procdump.ps1` 모듈은 임시 디렉토리에 주입된 Sysinternals의 `Procdump` 유틸리티를 프로세스 공간에 강제 매핑하여 덤프 파일을 물리적으로 생성하는 방식을 취한다.

```powershell
# Get-Procdump.ps1
Start-Process -FilePath ".\procdump.exe" -ArgumentList "-ma $TargetPID `"$DumpOutputPath`"" -Wait -WindowStyle Hidden
```

수집된 `.dmp` 파일은 분석 스테이션으로 안전하게 반환된 뒤, 프로세스 내부에 은닉된 악성 페이로드 셸코드나 메모리 상에 평문으로 잔존하는 자격 증명, C2 통신 주소 문자열 등을 추출하는 정밀 포렌식 아티팩트로 활용된다.

### 2. MEMORY

커널 레벨의 루트킷이나 파일리스 상태로 메모리에 상주하는 고도화된 위협을 탐지하기 위해 `Get-RekallPslist.ps1` 등의 메모리 분석 전용 모듈이 구동된다. 해당 모듈은 OS의 API가 제공하는 가상화된 프로세스 정보에만 의존하지 않고, 물리 메모리나 crashdump 파일 인터페이스에 직접 접근하여 커널 객체를 열거하는 방식을 취한다.

일반적인 WMI 기반 수집 모듈이 OS API를 변조한 루트킷이나 API 후킹 기법에 의해 은닉된 프로세스를 놓칠 수 있는 한계를 보완하기 위해, 해당 모듈은 시스템의 메모리 맵 객체를 raw 레벨에서 직접 핸들링한다.

```powershell
# Get-RekallPslist.ps1
[System.IO.File]::Open("\\.\pmem", [System.IO.FileMode]::Open, [System.IO.FileAccess]::Read)
```

이와 같이 커널 공간 내의 프로세스 활성 구조체 체인(`ActiveProcessLinks`)의 포인터를 직접 순회하며 은닉된 프로세스 자산까지 전수 조사를 수행한다. 수집 방식은 원격 호스트의 라이브 메모리 상태를 파싱하여 정상적인 프로세스 리스트와 대조하는 절차로 이루어지며, 이를 통해 API 수준에서는 은폐된 실질적인 메모리 침해 지표를 도출한다.

### 3. REGISTRY

시스템 재부팅 후에도 악성코드가 지속적으로 자동 실행되도록 설정하는 영속성 메커니즘을 식별하기 위해 `Get-Autoruns.ps1` 모듈이 작동한다. 이 모듈은 Windows 레지스트리 하이브의 주요 자동 실행 키(ASEP) 배열을 전수 조사하는 방식을 사용한다.

```powershell
# Get-Autoruns.ps1
$RunPaths = @(
    "HKLM:\Software\Microsoft\Windows\CurrentVersion\Run",
    "HKLM:\Software\Microsoft\Windows\CurrentVersion\RunOnce",
    "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run"
)
foreach ($Path in $RunPaths) {
    Get-ItemProperty -Path $Path | Select-Object -Property * -ExcludeProperty PSPath, PSParentPath, PSChildName
}
```

구체적으로는 서비스 등록 정보가 저장되는 `System\CurrentControlSet\Services` 경로 아래의 실행 파일 경로(`ImagePath`)와 드라이버 로드 옵션을 직접 조회한다.

단순히 레지스트리 키 이름만을 열거하는 것에 그치지 않고, 등록된 타깃 바이너리의 파일 경로를 역추적하여 파일의 생성 시간과 매핑 상태의 일치 여부까지 검증하는 방식을 채택한다. 이를 통해 사용자 모르게 드롭되어 시스템 시작 시 백그라운드로 구동되도록 예약된 백도어나 공격자의 비정상적인 영속성 등록 아티팩트를 일괄적으로 수집 및 선별한다.

### 4. DISK

디스크 상에 은닉되거나 겉으로 드러나지 않는 타임스탬프 변조 행위를 파악하기 위해 `Get-Mft.ps1` 모듈이 구동된다. 해당 모듈은 NTFS 파일 시스템의 핵심 관리 아티팩트인 `$MFT(Master File Table)` 파일 레코드를 raw 레벨에서 직접 파싱하거나 관련 파일 시스템 파일 스트림 API를 호출하여 디스크 내 모든 파일의 메타데이터를 추출한다.

```powershell
# Get-Mft.ps1
$DriveStream = [System.IO.File]::Open("\\.\C:", [System.IO.FileMode]::Open, [System.IO.FileAccess]::Read, [System.IO.FileShare]::ReadWrite)
# $MFT 레코드의 표준 정보(SI) 및 파일 이름(FN) 속성 영역 바이트 파싱 수행
```

확인하는 주요 아티팩트는 파일의 표준 정보(Standard Information) 속성과 파일 이름(File Name) 속성에 기록된 각각의 시간 정보(MACB: Modified, Accessed, Created, MFT Modified)다.

공격자가 악성 파일의 생성 시간을 정상 파일처럼 변조하더라도 두 속성 간의 시간 불일치 징후나 MFT 레코드 번호의 순서 왜곡이 발생하므로, 디스크 모듈은 이 스캔 데이터를 기반으로 시간 순서대로 정렬된 타임라인을 생성하여 특정 침해 시점 전후로 디스크 상에 가해진 모든 생성 및 변경 행위를 실증적으로 추적한다.

### 5. NETWORK

프로세스와 디스크 외부로 드나드는 실시간 위협 및 C2 통신을 포착하기 위해 `Get-Netstat.ps1` 모듈이 활용된다. 해당 모듈은 원격 호스트의 네트워크 스택을 조사하여 현재 활성화된 모든 TCP/UDP 연결 상태와 대기(Listening) 포트 정보를 수집한다.

```powershell
# Get-Netstat.ps1
netstat -naob | ForEach-Object { 
    # 반환되는 문자열 배열을 정형 객체로 매핑
    [PSCustomObject]@{
        LocalAddress  = $Matches.LocalAddress
        ForeignAddress = $Matches.ForeignAddress
        State          = $Matches.State
        PID            = $Matches.PID
    }
}
```

주요 수집 아티팩트는 로컬 주소, 외부 연결 IP 주소, 포트 번호, 그리고 해당 네트워크 세션을 소유하고 있는 프로세스의 PID이다.

동작 방식은 네이티브 Windows 소켓 API 및 내부 CLI 커맨드를 통해 네트워크 상태 객체를 받아오는 형태를 취하며, 반환된 데이터는 앞서 프로세스 모듈에서 수집한 PID 정보와 상관관계 분석(Correlation)을 통해 결합된다. 이를 통해 브라우저나 정상 시스템 프로세스로 위장한 바이너리가 지속적으로 외부의 미확인 해외 IP 주소나 알려진 악성 도메인으로 무단 비콘(Beaconing) 신호를 송출하는 포트 연결 흔적을 고속으로 잡아낸다.
