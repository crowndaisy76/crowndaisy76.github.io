# [Mangling]

Mangling(맹글링)은 프로그래밍과 컴파일러 설계에서 식별자(변수명, 함수명, 클래스명 등)를 원래의 의미를 알 수 없는 다른 문자열로 변환하는 과정을 의미한다. 소스코드의 가독성을 파괴하여 리버스 엔지니어링을 방해하거나, 실행 파일의 크기를 줄이고 네임스페이스 충돌을 방지하기 위해 널리 사용되는 기법이다.

## 1. 맹글링의 본질적 목적

* **가독성 제거**: 소스코드의 모든 변수와 함수를 `_0x4f2a`, `a`, `b`와 같은 무의미한 이름으로 바꿈으로써, 코드를 읽는 사람에게 정보 제공을 차단한다.
* **파일 용량 최적화 (Minification)**: 긴 이름을 짧은 기호로 치환하면 자바스크립트나 자바 바이트코드 같은 환경에서 전체 코드의 용량을 획기적으로 줄일 수 있다.
* **이름 충돌 방지**: 프로그래밍 언어 사양에 따라 동일한 이름의 식별자가 충돌하는 것을 방지하기 위해 컴파일러가 내부적으로 고유한 기호를 생성하는 표준 과정이기도 하다. (C++의 Name Mangling이 대표적이다.)

## 2. 주요 방식과 기술적 메커니즘

#### 1) 기호 기반 맹글링 (Symbolic Mangling)

가장 보편적인 방식으로, 사전 정의된 규칙에 따라 식별자를 순차적으로 바꾼다.

* **열거형 방식**: `a`, `b`, `c`... 와 같이 알파벳순으로 이름을 짓는다.
* **16진수/난수 방식**: `_0x123abc` 처럼 16진수 형태나 난수를 조합하여 고유한 식별자를 생성한다.

#### 2) C++ 스타일 네임 맹글링 (C++ Name Mangling)

C++은 함수 오버로딩을 지원하기 때문에 동일한 이름의 함수가 여러 개 존재할 수 있다. 컴파일러는 이를 구분하기 위해 함수의 인자 타입, 개수, 반환 타입 등을 조합하여 고유한 식별자를 생성한다.

* **예시**: `void foo(int a)`와 `void foo(double a)`라는 두 함수가 있다면, 맹글링 후에는 각각 `_Z3fooi`와 `_Z3food`와 같이 변환되어 링커가 구분할 수 있게 만든다.

## 3. 정적 분석에 미치는 영향

맹글링은 코드의 '의미적 맥락'을 끊어내는 강력한 도구다.

* **심볼 테이블(Symbol Table) 무력화**: 분석 도구가 코드를 파싱할 때 가장 먼저 보는 것이 심볼 테이블이다. 여기서 식별자들이 모두 맹글링되어 있으면, 함수나 변수가 어떤 역할을 하는지 짐작할 수 있는 '힌트' 자체가 사라진다.
* **추적의 난해화**: 특정 변수가 코드 전반에서 어떻게 쓰이는지 추적하려면 분석가가 일일이 맹글링된 기호를 메모하고 매핑해야 한다. 이는 분석가에게 극심한 인지적 부하를 주어 분석 속도를 현저히 늦춘다.
* **디컴파일 결과의 퇴화**: 고급 언어로 코드를 복원하는 디컴파일러도 맹글링된 기호는 복구할 수 없다. 결과적으로 디컴파일러가 뱉어내는 코드는 `var _0x1 = _0x2(_0x3);`와 같은 형태가 되어, 로직 복원에 치명적인 방해 요소가 된다.

## 4. 구조적 모델링

맹글링 알고리즘은 일반적으로 다음의 파이프라인을 따른다.

```typescript
// 추상적인 맹글링 알고리즘 로직
function mangle(scopeTree: ScopeTree) {
    let counter = 0;
    
    // 스코프를 순회하며 모든 식별자 노드(Identifier)를 추출
    scopeTree.identifiers.forEach(identifier => {
        // 기존 이름을 무작위 또는 시퀀스 형태의 새 이름으로 치환
        const newName = generateName(counter++);
        identifier.name = newName;
    });
}

```

맹글링은 단순히 이름을 바꾸는 작업처럼 보이지만, 실제로는 컴파일러의 식별자 관리 체계와 코드의 구조적 종속성을 완벽히 이해해야만 수행할 수 있는 정교한 변환 작업이다. 프로그램의 외형을 훼손하여 그 내부의 논리를 보호하는 가장 효과적인 은닉 기술 중 하나라고 할 수 있다.
