# [WinRM(Windows Remote Management)]

## 1. WinRM의 정의

WinRM은 분산된 네트워크 환경에서 하드웨어, 운영체제, 시스템 서비스를 상호 운용 가능한 표준 프로토콜로 관리하고 제어하기 위해 Microsoft가 구현한 원격 관리 인프라다. 이 기술은 업계 표준 그룹인 DMTF(Distributed Management Task Force)가 정의한 SOAP(Simple Object Access Protocol) 기반의 방화벽 친화적인 규격인 WS-Management 프로토콜을 준수하며, Windows 환경에서는 `WinRM`이라는 독립적인 백그라운드 서비스 인터페이스 형태로 상시 대기한다. 과거 Windows의 원격 제어 및 동적 자원 관리를 담당하던 DCOM(Distributed Component Object Model)이나 전통적인 RPC(Remote Procedure Call) 방식이 네트워크 통신 과정에서 임의의 포트를 무작위로 할당하여 방화벽 차단 정책과 충돌하고 복잡한 네트워크 매핑을 야기했던 한계를 극복하기 위해, WinRM은 웹 표준 전송 프로토콜인 HTTP(기본 포트 5985) 및 HTTPS(기본 포트 5986) 표준 포트 두 개만을 고정하여 관리 트래픽 채널을 단일화하는 구조를 취한다.

## 2. 내부 세션 처리 및 데이터 파이프라인 아키텍처

WinRM의 내부 세션 처리 및 데이터 파이프라인 아키텍처는 네트워크 인입점을 감시하는 리스너(Listener) 계층, 세션 엔드포인트를 통제하는 WSMAN 서비스 레이어, 요청된 원격 명령을 가상 환경에서 격리 및 구동하는 플러그인 인프라 구조로 유기적으로 연계되어 작동한다.

### 2.1 리스너(Listener) 및 라우팅 구조

관리자용 마스터 컴퓨터가 원격 제어 세션을 수립하기 위한 요청 패킷을 전송하면, 타깃 엔드포인트의 WinRM 리스너가 해당 트래픽을 수신하여 호스트 내부의 적합한 셸 인프라로 라우팅을 수행한다. 이때 주입된 원격 명령이나 PowerShell 스크립트 실행 요청은 호스트 네이티브 파워셸 플러그인 프로세스로 이계되어 하부 시스템 자원에 직접적인 간섭을 주지 않는 독립된 가상 실행 공간인 런스페이스(Runspace)를 프로세스 내부에 동적으로 생성한다.

### 2.2 SOAP 기반 데이터 직렬화 파이프라인

이 파이프라인 상에서 오고 가는 모든 데이터 교환은 XML 아티팩트 구조의 SOAP 메시지로 정형화되어 캡슐화되며, 호스트 내부에서 쿼리된 파일 시스템이나 커널 정보 등의 정형 객체(Object)들은 WinRM의 데이터 직렬화(Serialization) 엔진을 거쳐 XML 바이트 스트림으로 추상화된 뒤 전송되고 수신측에서 역직렬화(Deserialization) 과정을 거쳐 원본 개체 모델로 복원된다.

## 3. 다중 레이어 인증 및 구간 암호화 메커니즘

네트워크 세션을 경유하는 원격 제어의 특성상 발생할 수 있는 보안 취약점과 자격 증명 탈취 문제를 원천 차단하기 위해 WinRM 인프라는 다중 레이어 인증 메커니즘과 통신 구간 전체의 강한 암호화 프로토콜을 강제한다.

### 3.1 메시지 레벨 암호화 아키텍처

기본적인 물리 트래픽 보안은 전송 계층 보안인 TLS/SSL(HTTPS) 환경을 통해 구성되지만, 엔터프라이즈 환경의 특성상 디지털 서명 인증서 인프라가 미비하여 일반 HTTP(5985) 포트 채널을 사용하는 상태라 할지라도 통신 내용이 평문(Plaintext)으로 유출되지 않는 고유의 메시지 레벨 암호화 아키텍처를 독립적으로 구동한다.

### 3.2 공유 비밀키 기반 난독화 블록 형성

WinRM은 초기 연결 확립 단계에서 Active Directory 환경의 Kerberos 또는 Negotiate(NTLMv2) 챌린지-응답 핸드셰이크를 강제 수행하여 세션 참여자의 권한을 검증한 뒤, 인증 성공 시 도출되는 고유의 공유 비밀키(Session Key)를 생성한다. 이후 전송되는 모든 SOAP 암호화 블록은 웹 서비스 보안 규격에 따라 메시지의 헤더 정보만 가시성을 유지하고, 실제 민감한 제어 명령과 호스트 반환 결과가 담긴 바디(Body) 영역 전체를 커널 레벨에서 완벽히 대칭키 암호화하여 송수신하므로 패킷 스니핑 공격에 대응하는 강력한 기밀성을 유지한다.

## 4. 자원 할당 제어 메커니즘 (Throttling Policy)

WinRM 인프라는 원격으로부터 유입되는 다중 관리 명령이나 원격지 스크립트 실행 행위가 특정 엔드포인트 시스템의 로컬 연산 자원을 고갈시켜 가용성을 침해하는 시스템 마비 현상을 예방하기 위해 서비스 프로바이더 정책에 따른 엄격한 자원 할당 제어 메커니즘을 기본적으로 내장하여 작동한다. 이러한 시스템 리소스 보호 제어 정책은 Windows 레지스트리의 `WSMAN` 하이브 구성 내부에 할당 제한 최고 수치(Quota) 형태로 상시 정의되어 통제된다.

### 4.1 MaxShellsPerUser 및 MaxMemoryPerShellMB

동일 자격 증명의 고유 사용자당 가동할 수 있는 최대 동시 원격 가상 셸의 개수를 제한하는 `MaxShellsPerUser` 정책과, 원격 런스페이스 프로세스가 시스템의 물리 RAM 영역을 무단으로 점유하여 아웃 오브 메모리 장애를 유발하지 않도록 상한선을 제약하는 `MaxMemoryPerShellMB` 옵션이 자원 임계치를 통제한다.

### 4.2 MaxTimeoutms 및 임계치 제어

원격 프로세스의 오류나 행(Hang) 상태로 인한 무한 루프 진입을 차단하기 위해 단일 명령 프레임에 할당 가능한 최대 연산 지속 밀리초를 강제 정의하는 `MaxTimeoutms` 속성이 이에 해당한다. 따라서 대규모 자산 관리나 고부하 시스템 스캔 스크립트를 WinRM 파이프라인으로 원격 주입할 경우, 세션이 자원 임계값 초과로 강제 드롭되거나 거부 예외가 발생하지 않도록 마스터 환경에서 세션 옵션 파라미터를 통해 커넥션 타임아웃 주기를 사전에 조율하고 호스트의 쿼터 마운트 수치를 유동적으로 통제해야 정상적인 영속적 제어 권한이 담보된다.
