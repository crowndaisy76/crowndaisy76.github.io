# [Opaque Predicate]

Opaque Predicate(불투명 서술자)는 소프트웨어 보안 분야에서 프로그램의 제어 흐름을 은닉하기 위해 사용하는 논리적 장치다. **런타임 시에 결과값이 항상 참(True) 또는 거짓(False)으로 고정되어 있지만, 정적 분석 도구가 이를 즉각적으로 판별하기 어렵게 설계된 조건식**을 말한다.

## 1. 핵심 원리: 정적 분석의 허점

컴파일러나 분석 도구는 소스 코드를 제어 흐름 그래프(CFG)로 변환할 때, `if`와 같은 분기문이 등장하면 참인 경로와 거짓인 경로를 모두 분석 대상에 포함한다. Opaque Predicate는 이 분석 과정에 '실제로는 절대 실행되지 않는 가짜 경로(Dead path)'를 의도적으로 생성하여 분석기를 교란한다.

분석기는 이 가짜 경로가 실행될 가능성이 있다고 판단하여 코드 분석 효율을 떨어뜨리고, 결과적으로 코드의 논리 구조를 심각하게 왜곡시킨다.

## 2. 주요 구현 방식

#### 1) 불변의 수학적 성질 이용

수학적으로 항상 일정한 결과를 도출하는 식을 조건문에 삽입한다.

```javascript
// x에 어떤 정수가 와도 (x * x + x)는 항상 짝수이다.
if ((x * x + x) % 2 === 0) {
    // 실제 실행 로직
} else {
    // 절대 도달할 수 없는 가짜 코드 블록
}

```

#### 2) 복잡한 런타임 계산식 이용

컴파일 타임에 결과를 예측할 수 없도록, 런타임에 동적으로 계산되는 복잡한 변수 상태를 활용한다.

```javascript
// 식의 구조가 복잡하여 분석기가 런타임 이전에는 참/거짓을 판별하기 어렵다.
if (x * x - y * y > 0 || !(x * x - y * y > 0)) {
    // 항상 참(True)으로 평가됨
}

```

## 3. 기술적 기여와 효과

* **분석 공간의 복잡도 증대**: 정적 분석 도구는 프로그램의 모든 분기 경로를 검증해야 한다. Opaque Predicate가 코드 전반에 삽입되면 분석기가 추적해야 할 경로의 수가 기하급수적으로 늘어나 분석 시간이 급증한다.
* **제어 흐름의 난해화**: 모든 논리적 분기점마다 불투명한 조건식을 배치하면, 코드의 흐름을 그래프로 시각화했을 때 논리적 맥락을 파악할 수 없을 정도로 복잡하게 얽히게 된다.
* **분석 피로도 극대화**: 인간 분석가가 디컴파일된 코드를 읽을 때, 무엇이 실제 비즈니스 로직이고 무엇이 가짜 로직인지 구분하기 어렵게 만든다. Opaque Predicate는 수많은 '가짜 로직'을 코드 곳곳에 심어, 분석가가 코드의 핵심 맥락을 파악하는 데 방대한 시간을 쏟게 한다.

결과적으로 Opaque Predicate는 단순히 코드를 복잡하게 만드는 것을 넘어, 프로그램의 **의미론적(Semantic) 분석을 기술적으로 불가능하게 만드는 핵심적인 논리 은닉 기술**이다.
