# [Control-Flow Graph(CFG)]

Control-Flow Graph(CFG)는 프로그램이 실행되는 동안 취할 수 있는 모든 경로를 그래프 구조로 표현한 것이다. 컴파일러 최적화, 정적 분석, 보안 분석 등 소프트웨어의 동작을 논리적으로 이해해야 하는 모든 영역에서 핵심적인 토대가 된다.

## 1. 기본 구성 요소

CFG는 크게 두 가지 요소로 구성된다.

* **Nodes (Basic Blocks)**: 더 이상 분기하거나 분기되지 않는, 순차적으로 실행되는 코드의 최소 단위다. 블록 내의 코드는 항상 순서대로 실행되며, 블록의 시작과 끝 외에는 외부로 나가는 분기(Jump)가 존재하지 않는다.
* **Edges (Control Flow)**: 블록 간의 연결 관계를 나타낸다. 한 블록이 끝난 후 다음으로 실행될 수 있는 블록으로 향하는 방향성(Directed)을 가진 화살표다.

## 2. CFG의 구조적 특징

* **Entry Node**: 프로그램의 실행이 시작되는 지점이다.
* **Exit Node**: 프로그램의 실행이 종료되는 지점이다.
* **Branching**: `if`, `switch`와 같은 조건문은 하나의 노드에서 두 개 이상의 에지가 뻗어 나가는 형태로 나타나며, 여기서 실행 경로가 갈라진다.
* **Loops**: `for`, `while` 구문은 그래프 내에서 에지가 거슬러 올라가 다시 앞선 노드로 연결되는 '사이클(Cycle)'을 형성한다.

## 3. 정적 분석에서의 역할

CFG는 코드를 텍스트가 아닌 '논리적 흐름'으로 재해석하게 해준다.

* **도달 가능성 분석 (Reachability Analysis)**: 특정 코드 블록이 실행될 수 있는 경로가 존재하는지, 아니면 도달할 수 없는 'Dead Code'인지를 판단한다.
* **데이터 흐름 분석 (Data-Flow Analysis)**: 변수의 값이 CFG의 에지를 따라 어떻게 변화하고 전달되는지 추적한다. 이는 코드의 부작용(Side-effect)이나 잠재적 버그를 찾는 기초가 된다.
* **코드 최적화**: 사용되지 않는 경로를 제거하거나, 반복되는 연산을 루프 밖으로 꺼내는 등 프로그램의 성능을 높이는 최적화 단계에서 필수적으로 참조된다.

## 4. 보안 및 난독화 분석과 CFG

보안 관점에서 CFG는 코드의 지문(Fingerprint)과 같다.

* **구조적 식별**: 난독화를 거쳐 변수 이름이나 문자열이 변하더라도, 프로그램의 논리적 흐름인 CFG 구조는 비교적 견고하게 유지되는 경우가 많다. 따라서 유사성 분석(Similarity Analysis)을 통해 악성코드의 패밀리를 식별하는 데 사용된다.
* **난독화 대응**: 앞서 다룬 '제어 흐름 평탄화(Control-Flow Flattening)'는 바로 이 CFG를 의도적으로 복잡하게 만드는 기법이다. 평탄화는 선형적인 그래프를 거대한 허브-스포크(Hub-and-spoke) 형태로 변형하여, 정적 분석 도구가 정상적인 논리 흐름을 읽지 못하도록 방해한다.
