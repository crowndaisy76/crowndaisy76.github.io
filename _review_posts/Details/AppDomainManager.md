# [AppDomainManager Hijacking]

## AppDomainManager의 기본 개념과 .NET 런타임 아키텍처

AppDomainManager 하이재킹은 마이크로소프트 .NET 프레임워크의 핵심 구성 요소인 애플리케이션 도메인(AppDomain) 관리 메커니즘을 악용하는 정교한 방어 회피 및 권한 실행 전술이다. .NET 아키텍처에서 애플리케이션 도메인은 하나의 프로세스 내부에서 가동되는 여러 응용 프로그램을 상호 격리하여 안전하게 실행하기 위해 고안된 논리적인 가상 컨테이너 역할을 수행한다.

마이크로소프트는 개발자가 이러한 애플리케이션 도메인의 생성 방식, 로딩 규칙, 그리고 보안 정책을 커스텀하게 제어할 수 있도록 System.AppDomainManager라는 표준 클래스를 제공한다. 공인된 엔터프라이즈 소프트웨어는 이 클래스를 상속받아 호스트 환경의 초기화 단계를 통제하는데, .NET 공용 언어 런타임(CLR) 엔진은 프로세스가 시동될 때 대상 실행 파일과 매핑된 구성 파일을 참조하여 지정된 AppDomainManager 자산을 메모리에 로드하는 아키텍처적 특성을 지니고 있다.

## 하이재킹 공격 메커니즘과 동작 프로세스

공격자들은 .NET 공용 언어 런타임 엔진이 애플리케이션의 기본 메인 진입점 함수가 실행되기 전, 구성 파일의 지시문을 무조건 신뢰하고 먼저 파싱한다는 작동 순서의 허점을 파고든다. 하이재킹을 달성하기 위해 공격자는 정상적인 디지털 서명이 완료된 화이트리스트 기반의 .NET 실행 파일, 악성 코드가 심어진 커스텀 AppDomainManager 동적 링크 라이브러리(DLL), 그리고 이를 호출하도록 정밀하게 조작된 응용 프로그램 구성 파일(exe.config)을 하나의 폴더에 동시 선점 배치한다.

프로세스가 실행되면 공용 언어 런타임은 실행 파일과 동일한 디렉터리에 위치한 구성 파일 내부의 런타임(runtime) 섹션을 가장 먼저 판독한다. 구성 파일 내부에 주입된 appDomainManagerType 및 appDomainManagerAssembly 지시문은 런타임 엔진으로 하여금 합법적인 도메인 관리자 대신 공격자의 악성 DLL 어셈블리를 강제로 생성하도록 명령한다. 이로 인해 정상 프로그램의 실제 본래 기능 코드가 호출되기도 전에, 공격자의 악성 클래스 생성자와 초기화 루틴이 프로세스 제어권을 완벽히 가로채어 메모리 상에서 최우선으로 실행되는 파괴적인 실행 파이프라인이 확립된다.

## 탐지 우회 효과와 방어 및 완화 전략

위협 인텔리전스 및 엔드포인트 방어 관점에서 AppDomainManager 하이재킹은 전통적인 DLL 사이드로딩 기술보다 훨씬 은밀하고 치명적인 탐지 우회 효과를 제공한다. 일반적인 DLL 사이드로딩은 윈도우의 표준 파일 검색 순서나 가져오기 주소 테이블(IAT)의 의존성에 기반하므로 최근의 EDR 솔루션에 의해 행위 기반으로 포착될 확률이 높다. 반면 AppDomainManager 하이재킹은 .NET 매니지드 코드 환경의 정식 초기화 규격을 준수하며 구동되기 때문에 보안 센서의 가시성을 효과적으로 회피한다.

특히 악성 코드가 실행되는 시점이 프로세스 라이프사이클의 최초기 단계에 해당하므로, 공격자는 EDR 솔루션의 유저 모드 감시 API 훅이 프로세스 메모리에 완전히 안착하거나 윈도우 이벤트 추적(ETW) 및 맬웨어 검사 인터페이스(AMSI) 컴포넌트가 활성화되기 전에 해당 보안 함수들의 메모리 주소를 찾아내어 반환 코드로 강제 패치해 버리는 선제 무력화 공작을 전개할 수 있다.

따라서 방어자는 응용 프로그램 실행 파일과 매핑되지 않은 임시 경로에서 .config 확장자 파일이 변조되거나 새로 생성되는 행위를 실시간 모니터링해야 한다. 또한 윈도우 Defender 애플리케이션 제어(WDAC)나 AppLocker 정책을 수립하여 공인되지 않은 미인증 DLL 어셈블리가 신뢰된 .NET 프로세스 공간으로 로드되는 것을 차단하고, 서명되지 않은 하부 컴포넌트의 실행을 원천 금지하는 강력한 애플리케이션 화이트리스트 통제 전략을 도입해야 한다.
