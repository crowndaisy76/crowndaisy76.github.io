# [POP3(Post Office Protocol version 3)]
## POP3의 개념과 사서함 관리 모델

POP3는 원격 이메일 서버에 도착한 메시지를 사용자 로컬 기기의 메일 클라이언트로 다운로드하기 위해 고안된 가장 고전적이고 대표적인 응용 계층 네트워크 프로토콜이다. 기본적으로 TCP 110번 포트를 사용하여 통신을 수행하며, 원격 서버를 일종의 임시 우체국 사서함처럼 취급하는 아키텍처 특성을 지닌다. 사용자가 이메일 프로그램을 통해 서버에 접속하면 사서함에 적재되어 있는 메시지 전문을 로컬 장치로 완전히 복사해 가져온 뒤, 기본 설정에 따라 서버에 보관되어 있던 원본 메시지를 자동으로 삭제하는 다운로드 및 삭제 모델을 기반으로 동작한다. 이는 메일 서버의 저장 공간을 효율적으로 절약할 수 있다는 장점이 있으나, 스마트폰과 PC 등 다중 기기 환경에서 동일한 사서함의 읽음 상태나 폴더 구조를 실시간으로 동기화하여 관리하기 어렵다는 명확한 한계를 가진다.

## 통신 연결 및 세션 상태 변화 아키텍처

POP3 통신 세션은 클라이언트와 서버 간의 유기적인 명령 주고받기를 통해 인증(Authorization), 트랜잭션(Transaction), 업데이트(Update)라는 명확한 세 가지 상태 단계를 거치며 전환된다. 최초 클라이언트가 서버에 연결을 수립하면 인증 상태로 진입하여 자신의 계정 이름과 패스워드를 전송하고 사서함 접근 권한을 유효성 검증받는다. 인증이 성공적으로 완료되면 트랜잭션 상태로 마이그레이션되는데, 이 단계에서 클라이언트는 서버에 보관된 총 메일의 개수와 용량을 조회하고, 특정 이메일의 본문 텍스트를 로컬로 다운로드하며, 수거 완료된 메일에 대해 삭제 마크를 지정하는 등의 실질적인 이메일 처리 명령들을 수행한다. 최종적으로 사용자가 접속 종료 명령을 송신하면 세션은 업데이트 상태로 진입하며, 메일 서버는 트랜잭션 단계에서 삭제 요청을 받았던 이메일들을 사서함에서 실제로 영구 제거하고 가용 자원을 정리한 뒤 연결을 최종 차단한다.

## 보안적 약점과 APT 공격에서의 위험성

POP3 프로토콜의 가장 치명적인 아키텍처적 약점은 초기 설계 당시 통신 암호화 메커니즘이 전혀 고려되지 않았다는 점이다. 사용자가 메일 서버에 로그인하기 위해 입력하는 고유 아이디와 암호는 물론이고, 주고받는 이메일의 제목, 본문 내용, 첨부파일을 포함한 모든 데이터 패킷이 네트워크 상에 가공되지 않은 일반 평문 상태 그대로 노출된다. 이로 인해 보안성이 결여된 POP3 트래픽은 동일한 네트워크망 내부를 감시하는 공격자의 패킷 스니핑 공격에 무방비로 노출될 뿐만 아니라, 호스트 내부의 윈도우 소켓 라이브러리(ws2_32.dll) 통신 API 함수들을 가로채는 로컬 네트워크 후킹 기법에도 심각하게 취약하다. 공격자는 메일 클라이언트 프로세스가 서버와 주고받는 평문 스트림 데이터 프로토콜을 실시간으로 역파싱하여 기업 내부의 핵심 인적 자격 증명과 민감한 기밀 비즈니스 대화 첩보를 손쉽게 수집하고 유출할 수 있다. 따라서 현대 엔터프라이즈 환경에서는 이러한 평문 전송 솔루션을 전면 배제하고, SSL/TLS 암호화 레이어가 적용된 POP3S(TCP 995번 포트)나 동기화 성능이 고도화된 IMAP 프로토콜을 강제 적용하는 보안 정책이 필수적으로 요구된다.
