# [UAC (User Account Control)]

## UAC의 기본 개념과 윈도우 권한 아키텍처

사용자 계정 컨트롤(User Account Control, UAC)은 마이크로소프트 윈도우 운영체제에서 기본 사용자 권한과 관리자 권한을 엄격히 분리하여 악성 코드나 비인가 프로그램이 시스템 전역 시스템 설정을 무단 변경하지 못하도록 방어하는 핵심 보안 메커니즘이다. 윈도우 인프라에서 관리자 권한을 가진 계정이 로그인하더라도, 시스템은 보안 아키텍처 설계에 따라 해당 사용자에게 즉시 완전한 관리자 토큰을 부여하지 않는다.

대신 일반 표준 사용자 권한을 가진 분할 토큰(Split-Token)을 먼저 발급하여 일상적인 프로세스를 처리하도록 제한한다. 이후 특정 응용 프로그램이 시스템 파일 수정, 레지스트리 전역 변경, 디바이스 드라이버 로드 등 고권한 레벨의 작업(High Integrity)을 요구할 때만 UAC 알림창(보안 데스크톱)을 팝업하여 사용자의 동의나 관리자 자격 증명을 명시적으로 요구하는 구조를 취하고 있다.

## 타 엔드포인트 보안 솔루션과의 근본적인 차이점

UAC는 안티바이러스(AV), 엔드포인트 탐지 및 대응(EDR), 방화벽(Firewall)과 같은 외부 보안 솔루션과 구동 목적 및 통제 계층 측면에서 명확히 구별된다.

* **AV 및 EDR 솔루션과의 차이점:** 안티바이러스나 EDR 솔루션은 파일의 해시, 정적 시그니처, API 호출 흐름 등의 동적 행위를 프로파일링하여 해당 프로그램이 악성(Malicious)인지 선성(Benign)인지를 판별하고 차단하는 데 주력한다. 반면 UAC는 프로그램의 악성 여부를 판단하지 않는다. UAC의 유일한 목적은 운영체제 아키텍처 레벨에서 프로세스의 무결성 수준(Integrity Level)을 검증하고, 최소 권한의 원칙을 강제하는 권한 경계선 통제이다. 합법적인 정상 유틸리티라 하더라도 시스템을 변경하려 하면 UAC가 개입하며, 반대로 악성코드라 하더라도 표준 사용자 권한 내에서만 동작한다면 UAC 알림은 발생하지 않는다.
* **네트워크 방화벽과의 차이점:** 방화벽은 OSI 7계층 아키텍처에 기반하여 포트, IP 주소, 프로토콜 트래픽의 인바운드 및 아웃바운드 흐름을 제어하는 네트워크 경계 보안이다. 이와 달리 UAC는 로컬 호스트 내부의 커널 자원 및 프로세스 토큰 가시성 상태 전환만을 통제하는 로컬 액세스 제어 메커니즘이다.

## UAC 우회(Bypass) 메커니즘과 fodhelper 사례 분석

보안 탐지 우회(Defense Evasion) 관점에서 UAC 우회는 공격자가 이미 중간 무결성(Medium Integrity) 권한을 확보한 상태에서, UAC 동의 알림창을 화면에 띄우지 않고 자식 프로세스를 높은 무결성(High Integrity) 권한으로 승격시켜 실행하는 기술을 의미한다. 이는 주로 윈도우 자체 내장 시스템 바이너리 중, 사용자 편의성을 위해 UAC 프롬프트를 자동으로 패스하도록 설계된 자동 승격(autoElevate) 속성이 활성화된 신뢰된 파일들을 표적으로 삼는다.

대표적인 우회 모듈인 fodhelper.exe(Features on Demand Helper)는 윈도우의 선택적 기능을 관리하는 정상 바이너리이며, 매니페스트 내부에 자동 승격 옵션이 참(true)으로 설정되어 있다. 따라서 이 파일이 구동될 때 윈도우는 사용자 알림 없이 즉시 고권한 토큰을 부여한다. 공격자들은 이 프로세스가 가동되는 최초기 단계에서 특정 레지스트리 경로를 참조하여 하부 명령을 실행한다는 아키텍처적 허점을 역이용한다.

fodhelper.exe 프로세스는 실행 시 현재 로그인한 사용자의 레지스트리 하이브(HKCU) 경로인 Software\Classes\ms-settings\shell\open\command를 가장 먼저 탐색하여 연계된 구조를 로드하려 시도한다. 본래 이 경로는 표준 사용자 권한으로도 자유롭게 쓰기와 수정이 가능한 영역이다.

공격자는 이 경로의 기본값(Default) 문자열에 실행하고자 하는 악성 PowerShell 스크립트나 백도어 바이너리 경로를 주입하고, 제어 흐름을 가로채기 위해 DelegateExecute라는 이름의 레지스트리 문자열 값을 공백으로 생성해 둔다. 이후 중간 권한의 프로세스가 fodhelper.exe를 호출하면, 자동 승격 메커니즘에 의해 fodhelper는 High 무결성 상태로 구동되지만, 내부 로직에 의해 HKCU에 변조되어 있던 악성 명령어를 최우선으로 읽어 실행하게 된다. 결과적으로 사용자의 화면에는 UAC 동의 창이 전혀 발생하지 않은 상태에서 최종 악성 코드가 관리자 권한을 완벽히 획득하여 동작하는 파괴적인 권한 상승 파이프라인이 성립된다.

## 탐지 가시성 확보 및 방어 완화 전략

위협 헌팅 관점에서 UAC 우회 행위는 정상적인 윈도우 환경에서 발생하지 않는 비정상적인 레지스트리 아티팩트와 프로세스 트리를 생성하므로 명확한 탐지 지표를 남긴다. 방어자는 HKCU\Software\Classes\ms-settings 등 표준 사용자 경로 내부에서 구조적인 레지스트리 키 생성 및 값이 수정되는 이벤트를 실시간 모니터링하여 침해 징후를 조기에 식별해야 한다.

또한 fodhelper.exe나 컴퓨터 관리 도구(compmgmt.msc) 같은 자동 승격 대상 시스템 바이너리가 자식 프로세스로 cmd.exe, powershell.exe 등 커맨드 라인 인터프리터를 기동하는 프로세스 계층 아키텍처 이상 징후를 프로파일링해야 한다. 인프라 전반의 근본적인 완화를 위해서는 전사 그룹 정책(GPO)을 통해 사용자 계정 컨트롤 승격 프롬프트 동작 설정을 최고 등급인 '항상 알림'으로 강제 적용함으로써, 자동 승격 바이너리가 예외 조항을 타지 못하도록 아키텍처 방어벽을 견고히 다져야 한다.
