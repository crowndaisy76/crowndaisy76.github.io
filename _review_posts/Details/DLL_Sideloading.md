# [DLL Sideloading]

## DLL Sideloading의 기본 개념과 윈도우 라이브러리 검색 순위 메커니즘

DLL Sideloading은 윈도우 운영체제가 실행 파일 구동 시 필요한 동적 링크 라이브러리(DLL)를 탐색하는 검색 순서 규칙의 허점을 악용하는 대표적인 방어 회피 및 실행 전술이다. 응용 프로그램이 필요한 DLL 파일의 절대 경로를 명시하지 않고 공유 함수를 호출할 때, 윈도우 시스템은 사전에 정의된 표준 검색 순서에 따라 해당 라이브러리를 추적한다.

이 순서는 안전한 DLL 검색 모드가 활성화된 상태를 기준으로 실행 파일이 위치한 디렉터리를 시작으로 시스템 디렉터리, 16비트 시스템 디렉터리, 윈도우 디렉터리, 현재 작업 디렉터리, 그리고 시스템 환경 변수(PATH)에 등록된 경로 순으로 진행된다. 공격자는 이 검색 메커니즘에서 최상위에 위치하는 '실행 파일과 동일한 디렉터리' 공간을 주목하여, 정상 프로그램이 로드해야 할 진본 라이브러리와 동일한 명칭을 가진 악성 DLL을 해당 경로에 선점 배치하는 방식으로 프로세스의 제어 흐름을 가로챈다.

## 공격자의 악용 기법과 삼합체 아키텍처 흐름

실제 위협 환경에서 공격자들은 방어자의 엔드포인트 보안 솔루션을 우회하기 위해 정상 실행 파일, 악성 DLL 로더, 그리고 암호화된 최종 페이로드가 결합된 삼합체 구조의 패키지를 주로 구사한다. 공격자는 마이크로소프트나 유명 글로벌 제조사의 정식 디지털 서명이 완료되어 화이트리스트에 등록된 신뢰성 높은 정상 실행 파일을 전면에 내세운다.

사용자가 이 파일을 가동하면 EDR 솔루션은 유효한 서명을 인지하고 프로세스의 기동을 허용한다. 하지만 프로세스가 생성된 직후, 응용 프로그램은 동일한 폴더에 배치된 공격자의 악성 DLL을 검색 순서에 따라 자동으로 메모리에 로드하게 된다. 이 악성 DLL은 정상적인 내보내기 함수들을 그대로 포워딩하여 프로그램의 에러 발생을 방지하는 동시에, 자신의 초기화 루틴 내부에서 암호화된 최종 백도어 페이로드를 메모리 공간에 복호화하여 인젝션하는 은밀한 실행 파이프라인을 완성한다.

## 탐지 및 방어 관점의 인텔리전스 시사점

위협 헌팅 및 사이버 위협 인텔리전스 관점에서 DLL Sideloading은 정적 평판 분석을 무력화하는 강력한 전술이지만, 동적 행위 프로파일링 측면에서는 명확한 탐지 지표를 복합적으로 노출한다. 대표적으로 디지털 서명이 완료된 정상적인 프로그램이 평소에 구동되지 않던 임시 폴더나 사용자 쓰기 권한이 허용된 경로(예: AppData, ProgramData)에서 실행되면서, 동일 경로에 존재하는 미인증 라이브러리를 호출하는 행위는 전형적인 이상 징후로 식별된다.

따라서 방어자는 시스템 내부에서 신뢰된 프로세스가 로드하는 하부 DLL 파일들의 디지털 서명 일치 여부를 상시 검증하는 교차 모니터링 정책을 수립해야 한다. 또한 소프트웨어 개발 및 패치 관리 단계에서부터 응용 프로그램이 외부 함수를 호출할 때 SetDefaultDllDirectories API를 가동하여 로드 경로를 안전하게 제한하거나 절대 경로 매핑을 강제화함으로써, 시스템 내부에 잔존하는 검색 순서 하이재킹 취약점의 근본적인 발생 가능성을 차단해야 한다.
