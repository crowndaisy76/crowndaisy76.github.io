# [Password Filter]
## 윈도우 패스워드 필터의 기본 개념

윈도우 패스워드 필터는 기업 환경에서 고도화된 암호 복잡성 정책을 강제하거나 여러 시스템 간에 암호를 동기화하기 위해 설계된 합법적인 운영체제 확장 기능이다. 기본적으로 윈도우는 대문자, 소문자, 숫자, 특수문자 조합 등의 기본적인 암호 규칙을 제공하지만, 기업이 자체적인 암호 사전을 구축하여 특정 단어 사용을 막거나 사내의 독자적인 보안 규정을 적용하고자 할 때 이 패스워드 필터 모듈을 직접 개발하여 운영체제에 연동할 수 있도록 허용하고 있다.

## 로컬 보안 인증 하위 시스템과 패스워드 처리 구조

사용자가 시스템의 패스워드를 새로 설정하거나 변경할 때 윈도우의 핵심 보안 프로세스인 로컬 보안 인증 하위 시스템(LSASS)이 이 요청을 담당하여 정책 검증을 시작한다. 이때 LSASS는 시스템 레지스트리의 알림 패키지 항목에 등록된 모든 패스워드 필터 모듈들을 확인하고 순차적으로 호출한다. 복잡성 정책을 검사하거나 다른 인프라와 암호를 동기화하기 위해서는 암호화되지 않은 원본 데이터가 필수적이므로, LSASS는 등록된 모듈의 특정 API를 호출할 때 사용자의 계정 이름과 새롭게 입력된 일반 텍스트 형태의 패스워드를 가공 없이 그대로 파라미터로 전달하는 구조를 취한다.

## 침해 사고에서의 악용 원리

공격자는 패스워드 필터가 시스템 내에서 평문 암호를 합법적으로 취급한다는 구조적 특성을 완벽하게 역이용한다. 대상 시스템의 관리자 권한을 탈취한 공격자는 암호 정책을 검사하는 정상 파일로 위장한 악성 DLL을 시스템에 떨어뜨린 뒤, 이를 레지스트리의 LSA 알림 패키지 목록에 추가로 기입한다. 이후 대상 시스템이 재부팅되어 악성 필터가 LSASS 프로세스의 메모리에 성공적으로 로드되면, 사용자가 정상적으로 패스워드를 변경할 때마다 해당 악성 모듈이 평문 패스워드를 가로채어 몰래 숨김 파일로 기록하거나 외부로 유출하게 된다.

## 보안 관점의 시사점 및 방어 대책

패스워드 필터를 악용한 자격 증명 탈취는 복잡한 메모리 해킹이나 취약점 공격 도구 없이 윈도우의 정상적인 보안 정책 메커니즘에 기생하므로 기존 보안 솔루션의 탐지를 쉽게 우회한다. 더욱이 악성 모듈은 운영체제가 부팅될 때 윈도우의 가장 권한이 높은 핵심 보안 프로세스 내부에 탑재되므로 시스템을 재시작하더라도 그 지속성이 매우 견고하게 유지된다. 방어자는 보안 관제 시스템 및 EDR을 통해 LSA 레지스트리 경로에 출처를 알 수 없는 새로운 값이 추가되는 행위를 엄격하게 모니터링해야 하며, LSASS 프로세스에 로드되는 모든 DLL 모듈의 디지털 서명과 무결성을 상시 검증해야 한다.
