# [AiTM (Adversary-in-the-Middle)]

AiTM은 공격자가 통신하는 두 주체(예: 사용자 클라이언트와 정식 인증 서버) 사이의 통신 경로에 위치하여 모든 트래픽을 가로채고, 수정하거나, 실시간으로 중계하는 공격 기법이다. 과거의 단순 패킷 스니핑이나 세션 하이재킹(Session Hijacking) 기법이 진화한 형태로, 최근에는 다중 인증(MFA) 체계를 무력화하는 자격 증명 탈취 전술로 널리 활용된다.

## **1. 기술적 작동 원리**

현대적인 AiTM 기법은 주로 **역프록시(Reverse Proxy) 아키텍처**를 기반으로 동작한다. 공격자가 자격 증명뿐만 아니라 최종 발급되는 세션까지 확보하는 프로세스는 다음과 같다.

* **실시간 트래픽 프록시:** 사용자가 공격자가 구성한 중계 서버(Proxy)에 접속하면, 중계 서버는 실제 정식 서비스의 로그인 페이지를 실시간으로 미러링하여 사용자에게 보여준다. 사용자가 입력하는 ID와 패스워드는 공격자 서버를 거쳐 정식 서비스 서버로 실시간 중계된다.
* **인증 챌린지 릴레이:** 정식 서버가 2차 인증(MFA 푸시 알림, OTP 코드 등)을 요구하면, 중계 서버는 이 요구를 그대로 가로채어 사용자 화면에 포워딩한다. 사용자가 인증을 완료하면 이 값 역시 정식 서버로 중계된다.
* **세션 쿠키 탈취:** 인증이 최종 승인되면 정식 서버는 사용자의 브라우저를 위해 유효한 세션 토큰을 발행한다. 이때 통신 경로에 있던 중계 서버가 이 세션 쿠키를 중간에서 복사하여 저장한다. 이후 공격자는 탈취한 쿠키를 자신의 브라우저에 주입함으로써, 대상의 아이디/비밀번호나 MFA 인증 장치 없이도 정식 인증된 세션을 그대로 탈취하게 된다.

## **2. 유사 자격 증명 탈취 기법과의 비교**

인증 정보를 노리는 다른 기법들과의 차별점은 '통신의 실시간성'과 '탈취 대상의 유효성'에 있다.

* **정적 자격 증명 수집 (Credential Harvesting):** 가짜 페이지를 통해 사용자가 입력한 ID와 패스워드만 데이터베이스에 저장하는 방식이다. 구현이 간단하지만, 대상을 제외한 환경이 MFA를 요구하는 상태라면 1차 자격 증명만으로는 로그인이 불가능하므로 차단된다.
* **전통적 세션 하이재킹 (Session Hijacking):** 이미 활성화된 사용자의 세션을 가로채는 기법이다. 주로 로컬 시스템에 침투해 브라우저 메모리를 덤프하거나 암호화되지 않은 네트워크 패킷을 스니핑해야 하므로, 현대적인 TLS/HTTPS 암호화 통신 환경에서는 성공률이 매우 낮다.
* **역프록시 기반 AiTM:** 로그인 프로세스가 시작되는 시점부터 트래픽을 중계하기 때문에, HTTPS 암호화 통신 구조에서도 사용자는 공격자 서버와 암호화 터널을 맺고 공격자 서버는 정식 서버와 암호화 터널을 맺는 방식으로 무력화한다. 결과적으로 MFA가 통과된 직후 생성되는 유효한 세션 자체를 낚아챈다.
